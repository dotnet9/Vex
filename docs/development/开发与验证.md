# 开发与验证

## 环境与启动

使用 Git、`global.json` 指定的稳定版 .NET 10 SDK。主程序依赖 Avalonia 12、AvaloniaEdit、Prism / DryIoc、ReactiveUI、Semi / Ursa 及 CodeWF 系列 NuGet。日常运行不需要原型的 Node.js 依赖。

```powershell
dotnet restore Vex.slnx
dotnet build Vex.slnx -v:minimal
dotnet run --project src/Vex/Vex.csproj -f net10.0
```

先从 [架构与源码导读](../概要设计.md) 找到职责对应文件，再修改 ViewModel、服务和资源。XML 统一两个空格缩进；包版本只维护在 `Directory.Packages.props`，产品版本只维护在 `Directory.Build.props`。

## 共享库本地联调

共享库通过 NuGet 引用，不引入跨仓 `ProjectReference`。需要调试共享库改动时执行：

```powershell
pwsh scripts/prepare_local_libraries.ps1 -PackageVersion <待验证版本>
```

使用脚本输出的临时 NuGet 配置与包目录还原；不要将本机路径、临时源或预览包误带入正式发布。正式 CI 从 nuget.org 恢复；本地功能和原生门禁通过后，才进入正式发布步骤。

## 选择验证范围

| 变更范围 | 入口 |
| --- | --- |
| 构建和依赖 | `dotnet build Vex.slnx -v:minimal` |
| 更新状态与安装交接 | `dotnet run --project scripts/update-verification/UpdateVerification.csproj -c Release` |
| 偏好持久化 | `dotnet run --project scripts/settings-verification/SettingsVerification.csproj -c Release` |
| 应用离屏回归 | `dotnet run --project scripts/ui-verification/UiVerification.csproj -c Release -- vex ./artifacts/ui-verification` |
| 七类设置真实绑定 | 同一验证器使用 `settings-ui` / `settings-real-ui` 模式 |
| 八布局与独立窗口 | 同一验证器使用 `workspace` 模式 |
| 编辑命令、四语与桌面布局 | 同一验证器使用 `editing-tools` / `locale` / `desktop-parity` |
| 关于视觉 | `scripts/about-visual-verification/AboutVisualVerification.csproj` |
| 加载与切换性能 | `scripts/performance-verification/PerformanceVerification.csproj` |
| 安装器与资产契约 | `scripts/tests` 及 `scripts/installer/tests`，见 [安装器维护](安装器维护.md) |
| 原型脚本、资源、离线文档 | `node design/scripts/verify.cjs` |
| 原型设计准则、对比度与完整写作流程 | `node design/scripts/browser-design-principles.cjs` |
| 原型八布局、焦点与章节回归 | `node design/scripts/browser-workspace-chrome.cjs` |
| 原型配色、排版、图表、表格与安装流程 | `node design/scripts/browser-resource-review.cjs` |

离屏宿主应使用独立配置、测试草稿和输出目录，不注册自己为默认 Markdown 程序，不覆盖用户文件。验证器各模式参数见 [界面验证说明](../../scripts/ui-verification/README.md)；计时口径见 [性能验证说明](../../scripts/performance-verification/README.md)。

测试通过后按变更补充必要的真实窗口检查：焦点、中文输入法、表格内容列宽、菜单边界、多 DPI、跨屏、文件冲突、未保存退出与原生安装。不要将 Headless 截图称为真实系统安装或输入法验收。

三份浏览器脚本是可选检查，需要本机 Node.js 能找到 Playwright，并预先启动原型预览服务。默认使用 Playwright 的 Chromium；Windows 可设 `$env:VEX_BROWSER_CHANNEL='msedge'` 使用已安装的 Edge。可通过 `VEX_PREVIEW_URL` 和 `VEX_CAPTURE_DIR` 指定服务地址与截图输出目录；未配置时截图写入 `artifacts/prototype-*`。这些依赖不影响普通原型预览或 .NET 应用启动。

## 国际化与资源

四种界面语言为简体中文、繁体中文、英文、日文。JSON 位于 `src/Vex/I18n`，修改资源后更新强类型映射：

```powershell
dotnet tool restore
dotnet tool run t4 -- src/Vex/I18n/Language.tt -o src/Vex/I18n/Language.cs
```

应用默认语言资源随程序集提供，应用 JSON 输出到 `I18n/Vex/`。根目录 `logo.svg`、`logo.png`、`logo.ico` 是应用图标源，通过 MSBuild Link 引用。浏览器原型的视觉资源见 [外观资源](../resources/外观资源.md)，不自动加入安装包。

## 发布前后

本地当前平台发布使用 `pwsh scripts/publish.ps1 -RuntimeIdentifier win-x64`；在对应系统替换为其 RID。NativeAOT 需要本机编译工具链。Release 仅提供 EXE、DEB、DMG 和 SHA256，完整矩阵和 Tag 流程见 [发布规范](../RELEASE.md)。提交、推送、Tag 与发布按本次维护任务的授权执行，文档中的流程不表示已获得这些操作的授权。

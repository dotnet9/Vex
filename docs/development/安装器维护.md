# Vex 安装器

Vex 的实际安装包由 `scripts/installer` 目录及 `scripts/Vex.iss` 独立维护，只消费发布目录载荷，不读取相邻仓库或应用源码。应用发布完成后，安装器只消费指定发布目录中的载荷，无需为修改安装界面重新构建应用。

Windows 产品入口使用 `Vex.Setup.iss`：640×360，左侧 180px 绿色品牌区、右侧单标题和主操作，跟随系统浅深主题。目录与两个安装选项折叠在“自定义安装选项”，展开仍保持窗口尺寸；完成页使用居中的勾选、两行标题和“写点什么”。MIT 完整原文可滚动查看，原生安装引擎负责文件占用、取消、回滚与启动应用。维护页提供打开、修复、卸载与安装详情，沿用精确 AppId 探测与已注册卸载器校验；卸载保留系统原生确认与进度窗口。静默安装继续使用 Inno 的命令行参数。

品牌位图由 `node scripts/installer/render-brand.cjs` 从原型 SVG 生成，需要开发环境提供 `sharp`；安装包只嵌入离线 BMP。`verify_vex_visual.ps1` 在独立桌面检查真实中英文、明暗主题、维护和迁移流程，不切换用户桌面。`compare_vex_visual.py` 默认比较中文原型的初始、展开选项、进度、完成、维护共十张截图，同时记录原始 RGB 与 1px 字体栅格容差后的相似度。英文无原型页面，完整许可与特殊维护场景通过独立交互检查，不计入该图像指标。

Vex 品牌固定为 **维刻 / Vex**，简体中文 Slogan 为 **维刻 Vex · 写下想法，看见脉络。**。macOS 使用精简的 Finder 拖放背景，Linux 使用标准软件管理器读取的产品元数据。二者的系统授权与复制、安装、移除交互仍由操作系统处理。

独立验证入口：`tests/Vex.Fixture.iss` 与 `tests/verify_vex_fixture.ps1`。夹具只将 LICENSE 复制到指定临时目录，不注册、不建快捷方式、不启动应用；在独立桌面验证，不切换用户桌面。生产脚本可用 `scripts/tests/windows_setup_contract_test.ps1 -Compile -InnoSetupCompiler <ISCC.exe>` 在独立副本中编译受控载荷。

## 共享基础快照

源目录为 CodeWF.Avalonia 的 `scripts/installer`。所有 App 与两个 Demo 在各自仓库保留完整快照，打包不读取相邻仓库。`source-sha256.json` 记录共享源摘要；文本统一 LF，位图保持二进制。

## Windows

保留的 `CodeWF.Setup.iss` 是共享基础快照，以下说明用于其独立夹具与来源校验；Vex 产品入口已切换到上面的专用外观。共享层使用 Inno Setup 6 的原生页面与 Windows GDI，主色为 `#512BD4`，无需 WebView、联网下载或第三方皮肤 DLL。

- 实际窗口区域为凹缺、突出左舱、右切角和阶梯底边。标题栏支持拖动与最小化，按钮保留原生键盘和焦点行为。
- 深色、浅色、跟随系统循环切换；默认深色。系统外观只读，不修改用户个性化设置。
- 八角 CodeWF 品牌核心、轨道与粒子响应真实安装进度，主色继续采用 .NET 紫。核心使用可聚焦的原生按钮，点击通过默认浏览器访问 `https://codewf.com`，不在安装时自动打开网页。
- 品牌动画和进度先在可复用离屏位图完成，再一次提交整帧；品牌按钮禁止背景擦除，整数百分比未变化时不重复更新文本和进度。减少动态效果时停止粒子及呼吸动画；隐藏和最小化时停止绘制。生产流程不注入测试等待时间。
- MIT 许可保留各仓库原文，界面支持简体中文和英文。许可、目录、安装任务和完成启动项由 Inno 正常处理。
- 维护入口只匹配自身精确 AppId。修复复用正常安装，卸载打开已验证的注册卸载器；成功后关闭安装向导，禁止继续安装。
- 独立卸载窗口使用相同品牌资源，百分比读取原生进度条。资源放在 `{app}\.codewf-installer` 并由 Inno 卸载日志精确清理。保留未登记文件，不递归清空安装目录。

使用 32 位 Inno Setup 引擎编译；产品载荷仍为 Windows x64 NativeAOT。当前 GDI 回调按该引擎 ABI 定义，升级编译器时必须保留引擎架构并运行原生夹具。

```powershell
ISCC.exe scripts/<产品名>.iss /DAppVersion=<版本> /DSourceDir=<NativeAOT发布目录> /DOutputDir=<安装包目录>
```

`scripts/installer/tests` 中的安装夹具不创建卸载注册、快捷方式或文件关联，也不启动产品。原生 GUI 验证器在独立桌面运行，不切换用户桌面；正式产品安装器只编译，不在开发机替用户执行安装。维护逻辑检查预处理结果，确认夹具排除了真实注册探测和卸载启动。

Windows、Linux、macOS 的安装原型统一在 [design](../../design/index.html)。真实安装器实现位于 scripts/installer，浏览器演示不代替原生安装验证。

## macOS 与 Linux

`scripts/installer/macos/` 提供统一 DMG 背景与 Finder 拖放布局，生成 x64 / arm64 DMG；系统复制、覆盖、Gatekeeper 和授权仍由 macOS 处理。默认使用中英双语静态背景。正式交付格式为 DMG。

`scripts/installer/linux/` 提供统一品牌与 AppStream 元数据，生成 x64 / arm64 DEB。软件管理器外观及授权受发行版控制，不能由包文件统一为 Windows 异形窗口。

所有平台交付真实 EXE / DEB / DMG 与 SHA-256，不用 ZIP 代替安装包。Windows 夹具或受控 shell 测试不等同于真实 Linux / macOS 安装验收；签名、公证、多 DPI、多显示器及读屏仍需要相应环境检查。


## Linux 打包与元数据

Linux DEB 包包含应用本身的图标、桌面入口、中英文软件说明、MIT 许可与 Homepage，以及供软件管理器读取的 AppStream 元数据。PNG 按原始尺寸放入 hicolor，已有 SVG 同时放入 scalable；文件均随当前仓库独立打包。

`.NET` 品牌紫 `#512BD4` 通过 AppStream 的 `branding` 字段提供。软件管理器是否采用该颜色由发行版决定；DEB 不能统一替换系统安装器的窗口形状、动画或皮肤。包没有引用尚未发布的宣传截图。

维护 `scripts/installer/linux/product.json` 更新本仓库描述。公共生成脚本来源及 SHA256 记录在同目录 `source.json`，副本已包含在仓库中，打包不依赖其他仓库。

运行 `pwsh scripts/tests/linux_metadata_test.ps1` 检查元数据、图标、许可、桌面入口和体积。Windows 可验证暂存文件；真实 DEB 构建与软件管理器显示需在 Linux 使用 `dpkg-deb`、`appstreamcli validate` 和桌面环境验证。

运行 `pwsh scripts/tests/linux_packaging_test.ps1` 覆盖 x64/arm64 两种架构的暂存结构、语言资源、符号剔除、启动参数、校验和与失败传播，同时执行元数据检查。Windows 使用受控打包边界夹具，Linux 有 `dpkg-deb` 时调用真实打包工具；该测试不安装或启动产品。


完整版本和平台矩阵见 [发布流程](../RELEASE.md)。源码路径均相对仓库根目录。

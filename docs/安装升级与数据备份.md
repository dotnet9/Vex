# 安装、升级与数据备份

## 安装包

从 [GitHub Releases](https://github.com/dotnet9/Vex/releases/latest) 下载对应系统、架构的安装包及 `.sha256`。浏览器原型只演示安装流程；它不下载或安装真实程序。

| 平台 | 安装包 | 操作 |
| --- | --- | --- |
| Windows x64 | `Vex-v<版本>-win-x64-setup.exe` | 当前用户安装，可选快捷方式与 Markdown 打开候选 |
| Linux x64 | `Vex-<版本>-linux-x64.deb` | 系统软件包管理器，Debian 架构 `amd64` |
| Linux arm64 | `Vex-<版本>-linux-arm64.deb` | 系统软件包管理器，Debian 架构 `arm64` |
| macOS x64 | `Vex-<版本>-osx-x64.dmg` | 挂载后将 `Vex.app` 拖入应用程序 |
| macOS arm64 | `Vex-<版本>-osx-arm64.dmg` | Apple Silicon，复制完成后推出映像 |

当前正式发布为五个 RID，均为 NativeAOT。不将项目文件中的其他运行时或历史打包脚本视为公开发行承诺。Linux 包面向 DEB 生态；系统兼容性、macOS 签名与 Gatekeeper 以对应版本说明和真实系统检查为准。

## 文件关联与升级

Windows 安装器将 `.md`、`.markdown`、`.mdown` 注册为打开方式候选与右键入口，不强制替换默认程序。默认应用按系统设置选择；取消安装器选项后应用启动不应偷偷重新注册。Linux / macOS 安装包声明文档类型。

更新入口在帮助菜单和关于界面。下载需核对对应平台资产和 SHA256，缺少资产时打开发布页；Windows 确认安装器窗口就绪后才请求退出。Linux、macOS 的系统安装界面和权限由各自系统处理。

Windows 当前为当前用户安装；升级遇到历史全用户安装时有专门迁移流程。不能把普通覆盖安装当作跨范围迁移，真实 UAC、卸载、取消与回滚须单独验收，详见 [安装器维护](development/安装器维护.md)。

## 数据分开保存

| 数据 | 位置或来源 | 备份方式 |
| --- | --- | --- |
| 正式 Markdown 与附件 | 用户选择的文档目录 | 备份整个目录，保留图片相对路径 |
| 偏好设置 | `AppSettingsStore` / `AppConfigHelper` 管理的配置 | 关闭应用后备份实际配置文件；不要把安装目录当作配置目录 |
| 恢复草稿 | 系统 `LocalApplicationData/Vex/drafts`，Windows 通常为 `%LOCALAPPDATA%\Vex\drafts` | 关闭应用后复制，需要时先恢复为 Markdown |
| MCP 审计 | 系统 `LocalApplicationData/Vex/mcp-audit.jsonl`，超过约 1 MB 轮转 | 按需要保存并脱敏 |
| 更新日志与鸣谢 | 安装包 `docs` 资源 | 随版本提供，无需复制到用户目录 |

Linux / macOS 的系统特殊目录由运行时解析，不套用 Windows 的盘符和环境变量。MCP Token 当前属于应用配置中的敏感字段，备份或分享配置前应脱敏；不要将其当作系统安全存储的凭据保险箱。

恢复草稿不是永久备份。换机或卸载前，将所有未保存内容另存为普通 Markdown，再备份文档与附件；重要笔记可以使用独立版本管理或备份工具。先确认新环境可读写原文件，再清理旧安装与草稿。

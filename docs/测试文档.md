## 〇、如何使用本文档

1. **先读「一、测试环境准备总说明」**，把环境、样本、目录准备好；只需准备一次。
2. 按任意顺序执行各章；但**第 1 章（启动与引导）建议最先执行**，因为引导只在特定状态下弹出。各章内部场景尽量按编号顺序执行，前面的场景常为后面准备状态。
3. 每个场景按四段执行：
   - **前提**：进入该状态所需的文档、设置、视图；
   - **操作**：具体到按键和鼠标位置；
   - **预期**：可直接判定的结果。凡出现 ⚠ 的条目是产品已知行为/限制，不算缺陷（汇总见文末）。
4. 每个场景执行后建议记录：场景编号、通过/失败、实际现象、截图。涉及文件内容的判定（"文件内容是什么"）用任意文本编辑器打开目标文件核对，不要用 Vex 自身核对自身。
5. 场景中出现的默认值均来自当前源码（`src/Vex/Core/Services/EditorPreferences.cs`），与旧版文档不一致时以本文为准。

## 一、测试环境准备总说明

### 1.1 软件获取与启动

**方式 A：源码运行（推荐，测试人员可随时重置）**

```powershell
# 前置：按 global.json 安装对应 .NET 11 SDK（主分支使用 .NET 11 RC）
$vexWorkRoot = 'D:/github/temp_files/vex-dev'
dotnet restore Vex.slnx "-p:ArtifactsPath=$vexWorkRoot/artifacts"
dotnet build Vex.slnx --no-restore -v:minimal "-p:ArtifactsPath=$vexWorkRoot/artifacts"
dotnet run --project src/Vex/Vex.csproj -f net11.0 --no-restore "-p:ArtifactsPath=$vexWorkRoot/artifacts"
```

命令行参数（可在 `dotnet run --` 之后附加）：

| 参数 | 行为 |
| --- | --- |
| `<某个 .md 文件路径>` | 启动并打开该文件（含中文、空格路径） |
| `<某个文件夹路径>` | 启动并打开该文件夹作为工作区 |
| （无参数） | 启动为空白文档（不自动载入演示文档） |
| `--verify-runtime <独立目录>` | 内部验证入口，测试人员不使用 |

**方式 B：安装包**：从 GitHub Releases 下载 `Vex-v<版本>-win-x64-setup.exe` 与配套 `.sha256`，校验后按当前用户安装；安装时可勾选"注册 `.md`/`.markdown`/`.mdown` 打开候选"。

### 1.2 测试目录与样本建议

建议建立独立测试根目录（避免污染真实资料），下文统一称 `D:\vex-test\`：

```
D:\vex-test\
├─ 单文件\            # 放单个 .md 文件，用于"打开文件/最近文件/编码"场景
│   ├─ 样例编码-GB18030.txt
│   └─ 空白.md
├─ 工作区A\           # 用于"打开文件夹/文件树/Git"场景，建议 3~5 个 md + 2 个子文件夹
├─ 工作区B\           # 用于"多根工作区/跨根拖拽/跨根查找"场景
├─ 导出输出\          # 导出目标目录
└─ 裸仓库.git\        # git init --bare，用于 Git 推送/拉取本地替代
```

- 现成的长样本：仓库内 `docs/Markdown功能示例.md`（覆盖标题/列表/表格/公式/化学/Mermaid 等）与 `docs/演示文档` 目录（8 份文档、24 类 Mermaid 图表、本地插图）。建议把两者复制进测试目录使用。
- 建议手写一份《结构样本.md》用于导图/大纲/章节场景，内容至少含：H1 一级、两个 H2、每个 H2 下两个 H3、一个无序列表、一个任务列表、一个代码块、一个表格、一段 front matter（`---` 开头的 YAML）。
- 编码样本：用记事本"另存为 ANSI"或 PowerShell `Set-Content -Encoding GB18030` 生成 GB18030 文件一份；用 VS Code 生成 UTF-8 BOM、Big5 各一份。
- 外部修改样本：另准备一个能改文件的辅助程序（记事本即可）。

### 1.3 配置、数据位置与重置方法

| 数据 | 实际位置（代码取值） | 说明 |
| --- | --- | --- |
| 偏好配置 XML | `AppConfigHelper.GetDefaultConfigPath()`：优先环境变量 `APP_CONFIG_FILE` → 已存在的进程路径 `.config` → 已存在的同名 `.dll.config` → 默认进程路径 `.config` | 源码运行时通常在 `src/Vex/bin/...` 旁；**不要假定统一在 `%LOCALAPPDATA%`**，测试前先实际确认（设置界面改一个值后按修改时间找） |
| 崩溃日志 | `%LocalAppData%\Vex\crash\crash-*.log`（保留最近 10 份） | 未捕获异常落盘；应用无独立的 `%LocalAppData%\Vex\logs` 目录，运行期诊断以 crash 目录为准 |
| 恢复草稿 | `%LocalAppData%\Vex\Drafts\` | 按进程会话隔离；文件名 = 路径 SHA256 + 会话 GUID |
| 最近文件 | `%LocalAppData%\CodeWF\Vex\recent-files.txt` | 最多 5 项 |
| MCP 审计 | `%LocalAppData%\Vex\mcp-audit.jsonl`（超约 1 MiB 轮转 `.1.jsonl`） | 含敏感路径，勿外传 |
| 用户模板 | `%LocalAppData%\Vex\Templates\` | 系统自带模板在程序目录 `Templates\` |
| Git PAT 凭据 | Windows 凭据管理器，Generic 凭据目标 `vex/pat/<host>` | 控制面板 → 凭据管理器 → Windows 凭据 |

**重置设置（恢复出厂）**：

1. 关闭 Vex 全部窗口；
2. 删除（或改名备份）第 1.3 表中定位到的配置 XML；删除 `%LocalAppData%\CodeWF\Vex\recent-files.txt`；
3. 如需连草稿一起清空：删除 `%LocalAppData%\Vex\Drafts\`；
4. 重启 Vex → 应回到首次启动状态（弹出六幕引导、空白文档、默认外观青碧配色）。

**注意**：重置后首次启动会自动进入新手引导，不想被打断的场景请先在第 1 章完成引导并记住"重看入口"（帮助 → 新手引导）。

### 1.4 日志与诊断

- 崩溃日志：`%LocalAppData%\Vex\crash\`，文件名 `crash-日期-时间.log`。任何"应用闪退/无响应"场景，收尾时都应检查该目录是否新增文件。
- MCP 审计：`%LocalAppData%\Vex\mcp-audit.jsonl`，JSONL 逐行一条记录，可直接用文本编辑器打开核对（第 15 章）。
- 草稿目录：`%LocalAppData%\Vex\Drafts\`，第 18 章异常恢复场景要核对文件存在/消失。

### 1.5 环境矩阵建议

| 项 | 建议 |
| --- | --- |
| 显示器 | 至少一台 100% 缩放主屏；如有条件加一台异 DPI（如 150%）副屏用于第 17 章 |
| 输入法 | 中文 IME（微软拼音）必须在场；IME 组合输入属实机验收清单，见文末已知限制 |
| 分辨率 | 主测 ≥1280×820（默认窗口 1280×820、最小 800×480）；另需一轮 980×640 窄窗 |
| Git | 本机安装 git CLI（`git --version` 可用）；准备 GitHub Personal Access Token 一个（或用本地裸仓库替代，见 1.6） |
| 网络 | 大多数场景不需要网络；检查更新场景需要（可跳过） |

### 1.6 本地替代设施（无外网/无远端时）

- **Git 推送/拉取本地替代**：
  ```powershell
  mkdir D:\vex-test\裸仓库.git; cd D:\vex-test\裸仓库.git; git init --bare
  # 在 Vex 里对 工作区A 初始化仓库后，Git 面板"远程地址"填 D:\vex-test\裸仓库.git
  # 保存远程后即可推送/拉取；制造分叉：另克隆一份裸仓库、在新克隆里提交并推送，
  # 再回到原工作区提交不同内容后拉取，即可得到 NonFastForward 分叉提示。
  ```
- **MCP 真实客户端本地替代**：MCP 服务启动后，用任意能发 HTTP POST 的工具（PowerShell `Invoke-RestMethod`、curl）对 `http://127.0.0.1:<端口>/mcp/` 发 JSON-RPC（示例见第 15 章 TC-MCP-011）；或用设置页自带的"测试连接 / 读取当前文档 / 请求修改文档"按钮（走同一条协议链路）。
- **外部修改触发**：记事本打开同一文件 → 修改 → 保存；或 PowerShell `Add-Content -Path <文件> -Value '外部追加行'`。触发窗口约 500ms 防抖。

## 三、术语表

| 术语 | 解释 |
| --- | --- |
| **即时编辑** | 像 Typora 一样的"所见即所得"编辑：正文按 Markdown 渲染成块，点击某块直接在该块原位输入；`Ctrl+Enter` 完成本块，`Esc` 取消本块修改。源码与即时编辑全局互斥（同一时刻只有一个生效）。 |
| **源码编辑** | 基于 AvaloniaEdit 的纯文本 Markdown 编辑器，显示行号与语法高亮，编辑的就是原文。 |
| **阅读** | 只读渲染视图，虚拟化滚动、流式渲染；图片/公式/Mermaid 可点击放大；任务勾选框可点击并回写编辑器。 |
| **章节导图（导图）** | 把文档标题/段落解析成思维导图，可改标题、移动层级顺序并写回 Markdown。 |
| **八种布局** | 顶部布局入口提供的固定组合：即时、源码、阅读、导图、源码＋阅读、源码＋导图、即时＋导图、三视图。定义在 `src/Vex.Core/Models/WorkbenchLayoutOption.cs`。 |
| **工作区（文件夹根）** | "打开文件夹"挂载的目录树。支持多个根：主根（打开文件夹）+ 附加根（添加文件夹到工作区）。文件归属决定保存/图片/导出路径。 |
| **快速打开（Ctrl+P）** | 对"最近文件 + 当前文件夹文档"做不区分大小写包含匹配的浮层，上下键选择、回车打开。 |
| **命令面板（F1）** | 全部命令的检索与执行浮层，含快捷键展示。 |
| **大纲** | 右侧栏的标题结构列表，支持跳转、跟随当前章、折叠持久化。 |
| **查找替换（工作台级）** | Ctrl+F/H 打开的查找条，作用于当前文档全文（即时与源码共用）。 |
| **演示模式（F6）** | 临时进入全屏、按章节翻页讲解；退出恢复原布局与阅读位置。正文/大纲/导图三种子模式。 |
| **专注模式（F8）** | 隐藏侧栏与右下角文档工具（保留标题栏）的写作状态。 |
| **打字机模式** | 编辑时把光标行保持在视口垂直居中。 |
| **缩放坞** | 阅读/导图/演示右下角的悬浮拖动条控件（`VexZoomDock`），百分比只在拖动时以气泡浮出。 |
| **front matter（前置元数据）** | 文档顶部 `---` 包裹的 YAML 块；阅读/即时渲染为置顶元数据卡，源码保持原样，复制到平台时剥离。 |
| **MCP** | 本机 Model Context Protocol 服务：AI 客户端经 HTTP + Bearer Token 调用 29 个白名单工具读写当前文档，默认关闭。 |
| **span 行内样式** | 以 `<span style="...">` 行内标记保存的字号/前景色/背景色，源码与即时编辑共用三键入口。 |
| **对齐式外部替换** | 外部改写正文时按组做前缀/后缀匹配，只重建变化的中段，保留未变块的视图、光标与撤销历史（V2.2.0.0）。 |
| **撤销分组** | 连续输入间隔 ≤650ms 且长度变化 ≤32 字符合并为一条撤销；超过则断组。 |

## 第 1 章 启动与引导（TC-START）

**本章覆盖范围与对应源码位置**：首次启动行为、六幕新手引导、空白启动、命令行参数、单实例转发、演示文档与帮助文档独立进程、工作区恢复。
关键源码：`src/Vex/Program.cs`（单实例 `SingleInstance.TryAcquire`）、`src/Vex/Core/Services/SingleInstance.cs`、`src/Vex/Modules/Shell/Views/MainWindow.axaml.cs`（`MainWindow_OnOpened` 启动参数分发）、`src/Vex/Modules/Shell/ViewModels/WorkbenchGuideViewModel.cs`（六幕编排）、`src/Vex/Modules/Shell/Views/WorkbenchGuideView.cs`（聚光与门控）、`src/Vex/Modules/Shell/ViewModels/MainWindowViewModel.cs`（`OpenStartupDocumentAsync`、升级续接）。

### TC-START-001 首次启动与引导自动弹出

**前提**：按 1.3 节重置全部设置与草稿；桌面环境正常。

**操作**：双击启动 Vex（或执行 1.1 方式 A 的 `dotnet run`），等待主窗口出现。

**预期**：
1. 主窗口出现，尺寸约 1280×820、屏幕居中（无保存位置时 `CenterScreen`）；
2. 内容区为空白文档，无默认标题模板；左侧文件列表为空态（只有"打开文件夹"类动作）；
3. 自动弹出「快速上手」引导开场卡（标题"快速上手"，按钮「先不看」「开始吧」）；默认外观为"青碧"配色、浅色；
4. 标题栏显示文档名（未命名）与 Vex 品牌。

### TC-START-002 引导六幕完整走通（含门控与代点）

**前提**：TC-START-001 的引导开场卡在场。建议窗口 ≥1280 宽。

**操作**：
1. 点「开始吧」进入第 1 幕（即时与源码）；
2. 观察第 1 幕：程序自动打字机输出"成都游记"内容，段末出现【继续】按钮 → 点击继续；
3. 走到两级门（高亮布局按钮）：先亲手点被高亮的布局入口 → 画廊弹出后再亲手点高亮的「源码编辑」卡片；
4. 故意点错一次（点画廊中非高亮卡片）→ 观察纠正提示；
5. 继续走完第 2 幕（大纲与导图）、第 3 幕（正文排版，依次应用 简约→书卷→专栏→刊物）、第 4 幕（Mermaid 图表，自动切源码＋预览并等图表出图）、第 5 幕（演示模式，自动进出一次）、第 6 幕（保存与分享菜单演示）；
6. 在末屏点「开始自己的写作」退出。

**预期**：
1. 每个【演】动作都有对应气泡/卡片文案（不允许无说明的自动操作）；
2. 门控不设超时不判失败；点错卡片出现"这次选「××」"纠正语且等待继续；
3. 任意一步点卡片「继续」可代点目标，流程不卡死；
4. 第 4 幕等待图表真正出图后才继续（超时 5 秒降级放行）；
5. 退出引导后：正文还原为进入前内容（演练副本不残留）、撤销历史还原、布局/排版/滚动位置还原。

### TC-START-003 引导跳过、上一步与 Esc 退出

**前提**：重新进入引导（帮助 → 新手引导）。

**操作**：在第 2 幕点「跳过本段」；在第 3 幕点「上一步」；随后按 `Esc`。

**预期**：
1. 「跳过本段」直接铺设下一幕基线文档并进入下一幕；
2. 「上一步」回退一幕；

### TC-MCP-011 只读工具本地 HTTP 联调

**前提**：服务启动，Token 已知。PowerShell 脚本（本地替代真实客户端）：

```powershell
$ep = 'http://127.0.0.1:17891/mcp/'
$h = @{ Authorization = 'Bearer <Token>'; Accept = 'application/json, text/event-stream' }
# 1) initialize
$init = @{ jsonrpc='2.0'; id=1; method='initialize'; params=@{ protocolVersion='2025-06-18';
  capabilities=@{}; clientInfo=@{ name='manual-test'; version='0' } } } | ConvertTo-Json -Depth 5
Invoke-RestMethod -Uri $ep -Method Post -Headers $h -ContentType 'application/json' -Body $init
# 2) tools/list（同会话，带返回的 mcp-session-id 头）
# 3) tools/call: vex_get_current_document
```

**操作**：按脚本依次执行 initialize → tools/list → vex_get_current_document。

**预期**：initialize 返回协议版本 2025-06-18 与服务端能力；tools/list 列出 29 个工具（vex_get_current_document / vex_replace_current_document / vex_apply_text_edit / vex_insert_text / vex_replace_selection / vex_replace_text / vex_undo / vex_redo / vex_open_document / vex_create_document / vex_save_current_document / vex_refresh_preview / vex_get_document_outline / vex_get_selection / vex_get_rendered_html / vex_get_app_status / vex_get_operation_audit / vex_list_files / vex_ui_* 系列）；错误 Token 返回 401；正文修改类工具在无确认配置时按确认流程走。

### TC-ERR-002 恢复草稿预览与独立文档

**前提**：TC-ERR-001 的提示在场。

**操作**：点开恢复预览（全文可读）→ 确认恢复。

**预期**：恢复创建**独立未保存文档**（无原路径，需另存），不直接覆盖来源文件；来源文件磁盘内容保持恢复前的样子；恢复后草稿来源标记清除。

### TC-ERR-003 正常关闭清理草稿

**前提**：文档有未保存修改。

**操作**：修改正文 → 等草稿落盘 → `Ctrl+W` 选「保存」→ 检查 Drafts 目录 → 再测一次选「取消」关闭。

**预期**：保存成功（或明确放弃）后**本会话草稿被清理**，下次启动不提示恢复；取消关闭则继续保留编辑与草稿。

### TC-ERR-004 保存失败重试（独占锁）

**前提**：当前文件已保存；用 PowerShell 以独占方式锁住该文件：

```powershell
$f = [System.IO.File]::Open('D:\vex-test\单文件\空白.md','Open','ReadWrite','None')
```

**操作**：修改正文 → `Ctrl+S` → 观察失败提示 → 解锁（`$f.Close()`）→ 点重试。

**预期**：保存失败出现危险态提示（存错通知条），正文、未保存状态与历史保持；继续输入不清除失败标记；解锁后重试成功保存**最新**内容；取消重试不显示成功。

### TC-ERR-005 只读文件

**前提**：把某文件设为只读（资源管理器属性）后打开并修改。

**操作**：`Ctrl+S`。

**预期**：保存失败有独立提示与重试入口；去除只读后重试成功；全程正文不丢失。

### TC-ERR-006 损坏配置回退

**前提**：关闭 Vex；把配置 XML 改为非法内容（如截断一半）；重启。

**预期**：应用能启动并回退默认值（含已删除排版键回退简约排版的历史回归点），不崩溃；首次操作后重新写出合法配置。

### TC-ERR-007 损坏草稿共存

**前提**：在 `%LocalAppData%\Vex\Drafts\` 手工放一个内容损坏的 `.json` 草稿 + 一个有效草稿（用 TC-ERR-001 生成）。

**操作**：重启应用查看恢复提示。

**预期**：损坏数据不直接删除（保留原数据）、不影响有效草稿的恢复流程；界面无崩溃。

### TC-ERR-008 未保存关闭保护三选

**前提**：主窗口有未保存修改。

**操作**：点窗口 ✕ → 依次体验 保存 / 丢弃（放弃）/ 取消。

**预期**：保护框按系统保存框样式（保存 + 丢弃/放弃 + 取消）；保存或明确放弃后窗口关闭且草稿清理；取消回到编辑；保存失败时阻止关闭（保留窗口与正文）。

### TC-ERR-009 外部对比对话框细节

**前提**：TC-DOC-016 的对比对话框打开，外部版本含：新增行、删除行、行内改词、连续 10 行相同。

**操作**：逐项核对差异渲染；双栏滚动；切换统一视图。

**预期**：行级 Myers/histogram LCS 正确；替换行词级高亮（中文按字符、英文按单词为词元）；>8 行未变更折叠为"⋯ 未更改的 N 行"可展开；长行不软换行（横向滚动）；双栏滚动同步；统一视图 `-` 红 `+` 绿单行号。

### TC-ERR-010 退出保留草稿失败

**前提**：制造草稿目录不可写（把 Drafts 目录设只读）；修改正文后点 ✕ 选「保存」到只读流程（或直接观察退出流）。

**操作**：观察关闭流程。

**预期**：草稿写入失败时**阻止关闭/继续提示**，不假报正常退出成功；恢复可写后重试成功才退出。⚠ 该路径人工难精确构造，允许以代码走读 + 观察项记录。

### TC-ERR-011 崩溃日志落盘

**前提**：任意状态。

**操作**：如测试过程中发生过闪退，检查 `%LocalAppData%\Vex\crash\`。

**预期**：未捕获异常生成 `crash-*.log`（保留最近 10 份）；无闪退则目录无新增（不算失败）。

### TC-ERR-012 清理不存在的草稿

**前提**：首次运行且 `%LocalAppData%\Vex\Drafts\` 不存在（删除整个 Vex 目录后重置启动）。

**操作**：正常关闭应用（无修改）。

**预期**：清理不存在的草稿不误报保存失败（历史修复点，V1.21.1.1）；静默正常退出。

## 第 19 章 性能冒烟（TC-PERF）

**本章覆盖范围与对应源码位置**：大文档输入热路径（V2.2.0.0 优化）、虚拟化滚动、视图切换、撤销预算、大目录。
关键源码：`src/CodeWF.Avalonia.Markdown/Editor/Controls/MarkdownLiveTextBuffer.cs`（每键缓存全文与组区间）、`docs/基准报告.md`（库层 229KB/3000 段 0.08ms/键 基线）、`src/Vex/Modules/Workspace/Views/MarkdownPreviewView.axaml.cs`（阅读虚拟化）。

### TC-PERF-001 大文档粘贴与打字

**前提**：新建文档；准备 5 万字纯文本（可脚本生成）。

**操作**：一次性粘贴进即时编辑 → 连续打字 1 分钟（含中文输入法）→ `Ctrl+Z` 数十次 → `Ctrl+Y` 数十次。

**预期**：粘贴后界面不长时间冻结（可接受一次性重建耗时）；每键输入无明显卡顿（热路径 0.08ms/键量级，人手应无感）；撤销/重做流畅；连续撤销到栈底不崩溃（200 条上限，超限从最旧丢弃）。

### TC-PERF-002 长文档滚动

**前提**：TC-PERF-001 的长文档切阅读视图。

**操作**：滚轮连续滚动 30 秒（到底再回顶两轮）；期间点击大纲跳转 3 次。

**预期**：滚动帧率无肉眼卡顿；离屏块虚拟化（物化控件数不随文档长度线性增长——可从任务管理器内存间接观察）；大纲跳转及时定位。

### TC-PERF-003 视图切换往返

**前提**：长文档。

**操作**：在八布局间快速往返切换 10 轮（即时↔源码↔阅读↔导图↔三视图）。

**预期**：每次切换可交互（无数秒假死）；历史记录 807 断言基线下切源码首帧 ~100ms 量级、返回即时 ~100ms 量级为参考，不作为硬门槛；切换后内容正确、光标合理。

### TC-PERF-004 大目录过滤

**前提**：一个 1000 文件的文件夹（脚本生成）。

**操作**：打开文件夹 → 过滤输入 → 清空 → 切列表/树。

**预期**：打开不冻结 UI（后台枚举）；过滤 250ms 防抖后快速出结果；列表 >200 溢出提示生效；切换流畅。

### TC-PERF-005 演示模式进出（长文档）

**前提**：长文档滚至中部。

**操作**：`F6` 进演示 → 翻 5 节 → `Esc` 退出；重复 3 轮。

**预期**：进出耗时无肉眼卡顿；退出后阅读位置准确回原章节（三轮都正确）；无内存持续增长表象。

> 注：本章为冒烟记录，不计较绝对毫秒数；如需量化请配合 `docs/基准报告.md` 的库层基准与验收文档 §4 的测量方法（记录文档规模、机器、构建类型）。

## 已知限制与预期失败项（不要误报为 bug）

以下条目引自 `docs/验收与已知限制.md`、`docs/更新日志.md`、`docs/需求文档.md` 与源码注释，测试中遇到时记录为"已知边界"，不算缺陷：

1. **长文阅读呈现层空白**：连续滚动后新暴露区域可能整段暂不渲染，交互（点击/再次滚动）后恢复；最小化再还原窗口可强制重绘。疑似远程桌面会话或特定显卡驱动下的 GPU 合成路径问题（SkiaSharp 预发布）。（README 待优化）
2. **手动保存非事务**：手动保存是直接异步写入（非临时文件替换），断电不保证文件不损坏；草稿不代替正式备份。（详细设计 §5.1）
3. **配置非跨进程事务**：配置写有进程内锁，但两个进程同时写不保证隔离。（详细设计 §6.1）
4. **Token 未入系统凭据库**：MCP Token 是普通配置字段，分享配置/日志/备份前需脱敏；Git PAT 例外，走 Windows 凭据管理器。（MCP 接口 §权限）
5. **侧栏全文搜索（FR-17）现状**：文件列表过滤当前按**文件名**匹配 + 悬停内容预览提示；"跨根搜索正文、按根分组、命中行摘要（≤3 行带行号高亮）与计数"尚未实现，属需求未达而非运行缺陷。（`ShellFilesViewModel.Projection.cs`）
6. **MCP 主题工具枚举有限**：`vex_ui_set_theme` 仅接受 system/light/dark，配色切换未作为独立工具暴露；`vex_ui_set_layout` 仍是布尔参数接口，不覆盖八布局名。（验收 §7 MCP 行）
7. **NativeAOT 发布版文件监视降级**：AOT 发布禁用 FileSystemWatcher 事件监控，文件列表依赖打开扫描与手动刷新。（更新日志 V1.24.0.0）
8. **仅 DIB 位图的截图工具不命中贴图**：剪贴板贴图支持资源管理器文件复制与 PNG 位图截图；个别老截图器仅 DIB 时回落文本粘贴。（验收 §7 IME/DPI 清单 4）
9. **中文 IME 与多 DPI 为实机验收清单**：IME 组合（PreeditText 路径、ImeProcessed 归一化）、多 DPI/跨屏在验收文档列为待补实机项；测试发现问题时按清单口径记录，非必然缺陷。（验收 §7）
10. **命令面板/水印/Git 错误等 i18n 已修但需回归**：V2.2.0.0 修复命令面板水印与按键提示、悬浮工具条视图徽标、GitService 六条异常的本地化；四语下出现中文残留才是缺陷。
11. **未开放分离视图入口**：`WorkspaceViewController` 独立视图窗口仅验证代码调用，正式界面无分离入口；"新建窗口"是完整新工作区。（概要设计 §3）
12. **Word 导出依赖服务层路径**：`ExportWordAsync` 返回空时 toast"导出未实现"；产物需实物打开复核，浏览器预览不等价于 PDF/PNG/Word。（详细设计 §8）
13. **macOS 菜单栏**：无系统原生应用菜单（NativeMenu）接入，macOS 靠窗体内自绘；Linux/macOS 安装器人工验收未全覆盖。（验收 §7）
14. **视觉一致性无全量量化**：98% 一致性目标仅覆盖 Windows 安装器指定十图的历史记录；工作台十场景均值 94.01%（2026-10-28 基线）。像素级观感差异不在功能测试判定范围。（验收 §1、§7）
15. **引导候选锚位**：引导卡片锚位只做过窄窗（980×640）容纳性检查，未逐条与原型对照；窄窗侧栏自动收起与 toast 的触发宽度阈值未按原型实测复核。（验收 §7 引导行）
16. **导图分支管理占位**：Git 面板分支按钮的「分支管理」是提示 toast 占位（GitBranchManagementToast），非完整分支管理功能。（更新日志 V1.25.0.0）
17. **演示导图倍率量程与主窗体不同**：演示内 0.15–3，主窗体导图坞 1–200%，属设计口径不是 bug。（ShellWorkbenchViewModel.MapZoomFloor/Ceiling）
18. **阅读视图表格悬停工具**（复制 Markdown/CSV/预览表格）依赖库版本行为，若入口缺失按观察项记录，先核对 CodeWF.Avalonia.Markdown.Lite 版本再定性。（更新日志 V1.9.0）

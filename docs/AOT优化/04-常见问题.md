## 编译错误

### Q1: 编译时提示找不到 `IContainerRegistry`

**错误信息**：
```
error CS0246: The type or namespace name 'IContainerRegistry' could not be found
```

**原因**：
- 文件中仍在使用 Prism 的 API
- 未正确替换为 Microsoft.Extensions.DependencyInjection

**解决方案**：
```csharp
// 错误
public void RegisterTypes(IContainerRegistry containerRegistry)
{
    containerRegistry.RegisterSingleton<IMyService, MyService>();
}

// 正确
public void RegisterServices(IServiceCollection services)
{
    services.AddSingleton<IMyService, MyService>();
}
```

---

### Q2: 编译时提示找不到 `PrismApplication`

**错误信息**：
```
error CS0246: The type or namespace name 'PrismApplication' could not be found
```

**原因**：
- `App.axaml.cs` 仍继承 `PrismApplication`
- 已移除 Prism NuGet 包

**解决方案**：
```csharp
// 错误
public partial class App : PrismApplication

// 正确
public partial class App : Application
{
    public IServiceProvider ServiceProvider { get; private set; } = null!;
    public static App? Instance { get; private set; }
}
```

---

### Q3: XAML 编译错误：找不到 `prism:RegionManager`

**错误信息**：
```
error MC3072: The property 'RegionManager.RegionName' was not found in type 'ContentControl'
```

**原因**：
- XAML 中仍在使用 Prism 的附加属性
- 命名空间未更新

**解决方案**：
```xml
<!-- 错误 -->
<ContentControl prism:RegionManager.RegionName="{x:Static regions:RegionNames.ShellSidebarRegion}" />

<!-- 正确 -->
<ContentControl regions:RegionManagerExtensions.RegionName="{x:Static regions:RegionNames.ShellSidebarRegion}" />
```

同时更新命名空间：
```xml
<!-- 移除 -->
xmlns:prism="http://prismlibrary.com/"

<!-- 添加 -->
xmlns:regions="using:Vex.Core.Regions"
```

## 运行时错误

### Q4: 应用启动时崩溃，提示服务未注册

**错误信息**：
```
System.InvalidOperationException: No service for type 'IMyService' has been registered.
```

**原因**：
- 服务未在 `ConfigureServices` 中注册
- 注册顺序错误（依赖的服务未先注册）

**解决方案**：
1. 检查 `ConfigureServices` 方法
2. 确保所有服务都已注册
3. 检查服务生命周期（Singleton/Transient/Scoped）

```csharp
private void ConfigureServices(IServiceCollection services)
{
    // 确保这个服务已注册
    services.AddSingleton<IMyService, MyService>();
}
```

### Q5: 区域中的视图没有显示

**症状**：
- 应用启动正常
- 但某个区域是空白的
- 无异常抛出

**原因**：
- 视图未注册到 DI 容器
- 视图未注册到 RegionManager
- 附加属性绑定错误

**排查步骤**：

1. **检查视图是否注册到 DI**：
```csharp
// 在 ConfigureServices 中
services.AddTransient<ShellFilesView>();
```

2. **检查视图是否注册到区域**：
```csharp
// 在模块的 Initialize 方法中
public void Initialize(IServiceProvider serviceProvider)
{
    var regionManager = serviceProvider.GetRequiredService<IRegionManager>();
    regionManager.RegisterViewWithRegion<ShellFilesView>(RegionNames.ShellSidebarRegion);
}
```

3. **检查 XAML 绑定**：
```xml
<ContentControl regions:RegionManagerExtensions.RegionName="{x:Static regions:RegionNames.ShellSidebarRegion}" />
```

4. **调试输出**：
```csharp
// 在 RegionManager.GetOrCreateRegion 中添加
Console.WriteLine($"Creating region: {regionName}");
Console.WriteLine($"View types to add: {viewTypes?.Count ?? 0}");
```

### Q6: 视图的 ViewModel 为 null

**症状**：
- 视图显示了，但功能不工作
- DataContext 为 null

**原因**：
- ViewModel 未注册到 DI
- ViewModel 未设置到视图的 DataContext

**解决方案**：

1. **注册 ViewModel**：
```csharp
services.AddSingleton<MyViewModel>();
```

2. **在视图中注入 ViewModel**：
```csharp
public partial class MyView : UserControl
{
    public MyView(MyViewModel viewModel)
    {
        InitializeComponent();
        DataContext = viewModel;
    }
}
```

或在视图创建时设置：
```csharp
// 在 RegionManager 中
var view = serviceProvider.GetRequiredService<ShellFilesView>();
var viewModel = serviceProvider.GetRequiredService<ShellFilesViewModel>();
view.DataContext = viewModel;
```

## 依赖注入问题

### Q7: 循环依赖错误

**错误信息**：
```
System.InvalidOperationException: A circular dependency was detected
```

**原因**：
- 服务 A 依赖服务 B
- 服务 B 又依赖服务 A

**解决方案**：

**方案 1：使用 Lazy<T>**：
```csharp
public class ServiceA
{
    private readonly Lazy<IServiceB> _serviceBLazy;
    private IServiceB ServiceB => _serviceBLazy.Value;

    public ServiceA(Lazy<IServiceB> serviceBLazy)
    {
        _serviceBLazy = serviceBLazy;
    }
}
```

**方案 2：引入中介者模式**：
```csharp
// 创建一个事件总线或消息中介
public interface IEventBus
{
    void Publish<TEvent>(TEvent @event);
    void Subscribe<TEvent>(Action<TEvent> handler);
}

// ServiceA 和 ServiceB 都依赖 IEventBus，而不是直接依赖对方
```

**方案 3：重构依赖关系**：
- 分析哪个依赖是必需的
- 提取共享逻辑到第三个服务

### Q8: 单例服务创建了多个实例

**症状**：
- 服务应该是单例，但发现创建了多次
- 状态不共享

**原因**：
- 注册为 `AddTransient` 而不是 `AddSingleton`
- 在不同的 ServiceProvider 中解析

**解决方案**：

1. **检查注册方式**：
```csharp
// 错误
services.AddTransient<IMyService, MyService>();

// 正确
services.AddSingleton<IMyService, MyService>();
```

2. **确保使用同一个 ServiceProvider**：
```csharp
// 错误：创建了新的 ServiceProvider
var newProvider = services.BuildServiceProvider();

// 正确：使用 App.ServiceProvider
var service = App.Instance.ServiceProvider.GetRequiredService<IMyService>();
```

---

### Q9: Scoped 服务在 Singleton 中使用

**错误信息**：
```
Cannot resolve scoped service from root provider
```

**原因**：
- Avalonia 桌面应用通常不使用 Scoped 生命周期
- Scoped 主要用于 Web 应用的请求作用域

**解决方案**：
- 桌面应用使用 Singleton 或 Transient
- 如果需要作用域管理，手动创建 ServiceScope：

```csharp
using (var scope = App.Instance.ServiceProvider.CreateScope())
{
    var service = scope.ServiceProvider.GetRequiredService<IMyScopedService>();
    // 使用 service
}
```

## 区域导航问题

### Q10: 区域中的视图无法切换

**症状**：
- 第一个视图显示正常
- 切换到第二个视图失败

**原因**：
- 自定义 RegionManager 的 ActiveView 切换逻辑有问题
- ContentControl 未绑定到 ActiveView

**解决方案**：

1. **检查 RegionManagerExtensions 绑定**：
```csharp
private static void OnRegionNameChanged(ContentControl control, AvaloniaPropertyChangedEventArgs e)
{
    // ...
    var region = regionManager.GetOrCreateRegion(regionName);
    
    // 初始绑定
    control.Content = region.ActiveView;
    
    // 监听变化
    region.PropertyChanged += OnRegionActiveViewChanged;
    
    void OnRegionActiveViewChanged(object? sender, PropertyChangedEventArgs args)
    {
        if (args.PropertyName == nameof(IRegion.ActiveView))
        {
            control.Content = region.ActiveView; // 关键：更新 Content
        }
    }
}
```

2. **检查 Region.ActiveView 属性通知**：
```csharp
public Control? ActiveView
{
    get => _activeView;
    set
    {
        if (_activeView != value)
        {
            _activeView = value;
            PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(nameof(ActiveView)));
        }
    }
}
```

### Q11: TabControl 区域不工作

**症状**：
- ContentControl 区域正常
- TabControl 区域不显示或报错

**原因**：
- 原 Prism 的 `TabControlRegionAdapter` 被删除
- 未实现自定义的 TabControl 适配器

**解决方案**：

**方案 1：不使用 TabControl 区域**（推荐）：
- 使用 ContentControl + 手动 Tab 切换逻辑

**方案 2：实现自定义适配器**：
```csharp
public class TabControlRegionBehavior
{
    private readonly TabControl _tabControl;
    private readonly IRegion _region;

    public TabControlRegionBehavior(TabControl tabControl, IRegion region)
    {
        _tabControl = tabControl;
        _region = region;
        
        // 同步视图列表
        _region.PropertyChanged += (_, e) =>
        {
            if (e.PropertyName == nameof(IRegion.Views))
            {
                _tabControl.Items = _region.Views;
            }
            else if (e.PropertyName == nameof(IRegion.ActiveView))
            {
                _tabControl.SelectedItem = _region.ActiveView;
            }
        };
        
        // 同步选中项
        _tabControl.SelectionChanged += (_, _) =>
        {
            if (_tabControl.SelectedItem is Control view)
            {
                _region.ActiveView = view;
            }
        };
    }
}
```

## Native AOT 问题

### Q12: Native AOT 编译失败，提示反射问题

**错误信息**：
```
Method 'ReflectionBindingExtension.ProvideValue' will always throw
```

**原因**：
- 代码中使用了反射绑定
- 某些库不兼容 Native AOT

**解决方案**：

1. **检查是否还有 Prism 残留**：
```bash
rg -i "prism" --glob "*.cs" --glob "*.axaml" src/
```

2. **检查反射绑定**：
```bash
rg "Bind\(" --glob "*.cs" src/Vex/ | head -20
```

3. **替换为 PropertyChanged 事件**：
```csharp
// 错误：反射绑定
textBlock.Bind(TextBlock.TextProperty, viewModel.GetObservable(x => x.Text));

// 正确：事件订阅
textBlock.Text = viewModel.Text;
viewModel.PropertyChanged += (_, e) =>
{
    if (e.PropertyName == nameof(viewModel.Text))
        textBlock.Text = viewModel.Text;
};
```

### Q13: Native AOT 编译成功，但运行时崩溃

**症状**：
- 编译没有错误
- 启动时崩溃或某功能崩溃

**原因**：
- 运行时反射调用（Type.GetType, Activator.CreateInstance 等）
- 裁剪器移除了必需的代码

**排查方法**：

1. **查看崩溃日志**：
```bash
# 运行 Native AOT 版本
.\artifacts\publish\win-x64\Vex\Vex.exe 2>&1 | tee aot-log.txt
```

2. **检查反射使用**：
```bash
rg "Type\.GetType|Activator\.CreateInstance|MethodInfo|PropertyInfo" --glob "*.cs" src/
```

3. **添加 DynamicallyAccessedMembers 属性**：
```csharp
public void ProcessType([DynamicallyAccessedMembers(DynamicallyAccessedMemberTypes.PublicMethods)] Type type)
{
    // AOT 知道需要保留此类型的公共方法
}
```

4. **使用 rd.xml 保留类型**：
```xml
<Directives xmlns="http://schemas.microsoft.com/netfx/2013/01/metadata">
  <Application>
    <Assembly Name="Vex" Dynamic="Required All" />
  </Application>
</Directives>
```

## 性能问题

### Q15: 替换后启动变慢了

**症状**：
- 启动时间从 2 秒变成 5 秒

**原因**：
- DI 容器构建耗时
- 服务初始化顺序不优

**解决方案**：

1. **延迟初始化**：
```csharp
// 不要在 ConfigureServices 时初始化
services.AddSingleton<IHeavyService>(sp =>
{
    // 仅在首次访问时创建
    return new HeavyService();
});
```

2. **异步初始化**：
```csharp
public override async void Initialize()
{
    // 同步部分
    AvaloniaXamlLoader.Load(this);
    
    // 异步初始化
    await Task.Run(() =>
    {
        var services = new ServiceCollection();
        ConfigureServices(services);
        ServiceProvider = services.BuildServiceProvider();
    });
    
    base.Initialize();
}
```

3. **分析性能**：
```csharp
var sw = Stopwatch.StartNew();
ConfigureServices(services);
Console.WriteLine($"ConfigureServices: {sw.ElapsedMilliseconds}ms");

sw.Restart();
ServiceProvider = services.BuildServiceProvider();
Console.WriteLine($"BuildServiceProvider: {sw.ElapsedMilliseconds}ms");
```

### Q16: 内存占用增加了

**症状**：
- 原版本 150 MB
- 新版本 200 MB

**原因**：
- 所有服务都注册为 Singleton
- 创建了不必要的对象

**解决方案**：

1. **检查生命周期**：
```csharp
// 频繁创建的对象使用 Transient
services.AddTransient<DocumentFile>();

// 状态对象使用 Singleton
services.AddSingleton<IAppSettings>();
```

2. **使用内存分析工具**：
```bash
# Visual Studio Memory Profiler
# dotMemory
# PerfView
```

3. **释放不用的资源**：
```csharp
public class MyService : IDisposable
{
    public void Dispose()
    {
        // 清理资源
    }
}

// 注册为需要释放的服务
services.AddSingleton<MyService>();
```

## 迁移决策

### Q17: 是否必须移除 Prism？

**回答**：

**如果你需要 Native AOT**：
- ✅ 必须移除
- Prism.Avalonia 使用反射绑定，与 AOT 不兼容

**如果你不需要 Native AOT**：
- ❌ 不必移除
- 继续使用裁剪模式即可（体积 37 MB）

**权衡**：
| 指标 | Prism (裁剪) | 无 Prism (AOT) |
|------|-------------|----------------|
| 体积 | 37 MB | < 50 MB |
| 启动速度 | 慢 | 快 |
| 内存占用 | 中 | 低 |
| 开发成本 | 低 | 高（2-3 天） |
| 风险 | 低 | 中 |

---

### Q18: 可以只替换部分 Prism 功能吗？

**回答**：

**不推荐**：
- Prism 的模块系统、DI、区域导航是紧密集成的
- 部分替换会导致不一致和维护困难

**如果非要部分替换**：
1. 先替换 DI（最核心）
2. 再替换模块系统
3. 最后替换区域导航

但这样会增加复杂度，不如一次性完全替换。

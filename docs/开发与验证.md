# 开发与验证

## 1. 环境与启动

先读 [概要设计](概要设计.md) 和 [详细设计](详细设计.md) 定位职责。需要 Git、`global.json` 指定的 .NET 10 SDK（10.0.100，latestFeature）。Node.js 用于原型，Python 用于部分验证；原生工具链见 [安装与发布](安装与发布.md)。普通应用不依赖 Node。

在仓库根目录运行，将中间文件和产物放到仓外：

```powershell
$vexWorkRoot = 'E:/github/temp_files/vex-learning'
dotnet restore Vex.slnx "-p:ArtifactsPath=$vexWorkRoot/artifacts"
dotnet build Vex.slnx --no-restore -v:minimal "-p:ArtifactsPath=$vexWorkRoot/artifacts"
dotnet run --project src/Vex/Vex.csproj -f net10.0 --no-restore "-p:ArtifactsPath=$vexWorkRoot/artifacts"
```

关联 restore / build / run 使用相同 ArtifactsPath，避免读取不同目录的旧 assets。解决方案包含 Vex 和 Vex.Controls 两个生产项目，主题资源随 Vex.Controls 一起构建和打包，验证器需单独构建。XML 两个空格缩进；产品版本维护于 `Directory.Build.props`，NuGet 版本维护于 `Directory.Packages.props`。

本次维护约定直接在各仓 `main` 开发，不创建分支；一个完整逻辑验证后用简体中文规范提交并推送。文档整理不重打产品标签。

## 2. 自研库 NuGet 联调

库在 `E:/github/Libs`，临时包在 `E:/github/temp_nugets`，中间产物在 `E:/github/temp_files`。本地默认编译目录为 `E:/github/temp_files/vex-build`；安装包、发布程序等交付产物放在 Vex 仓库的 `artifacts`。不使用 `E:/github/temp`，完成验证后清理不再需要的临时目录。Vex 不添加跨仓 `ProjectReference`。

```powershell
$vexLibraryVersion = '<本轮新的包版本>'
pwsh scripts/prepare_local_libraries.ps1 -PackageVersion $vexLibraryVersion -LibraryRoot E:/github/Libs/CodeWF.Avalonia -WorkRoot E:/github/temp_files/vex-libraries -PackageRoot E:/github/temp_nugets
```

[prepare_local_libraries.ps1](../scripts/prepare_local_libraries.ps1) 打包 Lang、Controls、Markdown.Lite、Markdown、MindView，更新 Vex 四个直接依赖版本，生成 `WorkRoot/NuGet.local.config` 并还原界面验证器。Lite 为传递依赖。脚本会修改中央版本文件，需先确定本轮版本；拒绝覆盖同版本包，可用 `-SkipPack` 复用完整包集。Linux 应显式指定实际 `Libs` 大小写路径。

继续构建沿用该配置与输出：

```powershell
dotnet restore Vex.slnx --configfile E:/github/temp_files/vex-libraries/NuGet.local.config -p:ArtifactsPath=E:/github/temp_files/vex-libraries/vex-artifacts
dotnet build Vex.slnx --no-restore -p:ArtifactsPath=E:/github/temp_files/vex-libraries/vex-artifacts
dotnet build scripts/ui-verification/UiVerification.csproj --no-restore -c Release -p:ArtifactsPath=E:/github/temp_files/vex-libraries/vex-artifacts
```

本地验证成功后更新库正式版本、提交推送并打库标签；确认线上 NuGet 可还原后再推 Vex 最终标签。开发联调无需等待线上包。临时源、nupkg、日志及机器配置不提交。

## 3. 按改动选择检查

| 改动 | 推荐验证 |
| --- | --- |
| 只有文档 | 本地链接、旧路径、`git diff --check`；原型链接变化再跑静态检查；来源 README 变化校验哈希 |
| 配置、偏好、折叠 | SettingsVerification + `preferences`、`file-tree`、`settings-real-ui` |
| 编辑、章节、布局 | `editing-tools`、`workspace`、`workbench`、`layout`，按需 `presentation` |
| 外观、国际化 | `prototype-appearance`、`prototype-chrome`、`desktop-parity`、`locale`、按钮状态 |
| 保存与恢复 | `protection`、`workspace`、`settings-real-ui` |
| 动画与释放 | `motion`，检查中间帧和快速显隐 |
| 更新交接 | UpdateVerification + `updates`，安装器窗口信号夹具 |
| 性能 | PerformanceVerification，固定机器、文档、运行时分轮测量 |
| 安装器 | 平台契约、隔离夹具、原生打包与运行时，见安装发布指南 |
| 较广功能改动收尾 | `vex` 完整流程；真实桌面专项按风险补充 |

检查通过后不因文档微调重复整套 AOT 和实机流程。失败保留非零退出码与证据，不能用其他层通过替代。

## 4. 界面验证器

验证器加载真实 App、MainWindow、XAML 模板和 VM，以 Avalonia.Headless + Skia 绘制。常规模式使用隔离或内存配置、草稿与最近记录，MCP 关闭，跳过宿主文件关联；测试文件复制到输出目录再编辑。`settings-real-ui` 特意使用仓外真实 XML 配置。

```powershell
$vexCheckRoot = 'E:/github/temp_files/vex-learning/ui'
dotnet build scripts/ui-verification/UiVerification.csproj -c Release "-p:ArtifactsPath=$vexCheckRoot/artifacts"
$vexVerifier = "$vexCheckRoot/artifacts/bin/UiVerification/release/UiVerification.dll"
dotnet $vexVerifier workspace "$vexCheckRoot/workspace"
dotnet $vexVerifier protection "$vexCheckRoot/protection"
```

参数形式为 `<模式> <输出目录> [专项参数]`，输出截图、JSON 和断言。

| 模式 | 覆盖 |
| --- | --- |
| `vex` | 完整流程、四语、主题、布局、编辑、浮层和六步引导 |
| `workspace` / `workbench` | 单文档八布局、章节拖动、共享历史、导航和引导恢复 |
| `layout` / `desktop-parity` | 尺寸、分隔条、菜单、辅助面板和独立窗口 |
| `prototype-appearance` / `prototype-chrome` | 原型资源、12 预览、三尺寸和工作台几何 |
| `editing-tools` | 格式、表格、编辑偏好和演示动作 |
| `settings-ui` / `settings-real-ui` | 七类设置、四语窄窗、语法、水印、图片、编码、自动保存及真实存储 |
| `preferences` / `locale` / `path-identity` / `file-tree` | 偏好、后台语言切换、路径身份和导航状态 |
| `protection` | 保存、导出、草稿失败、外部比较、恢复与退出保护 |
| `motion` | 入场中间帧、关闭动效、连续显隐及离树清理 |
| `updates` | 更新浮层、下载会话复用和安装失败 |
| `documents` | 帮助菜单 / 关于页共用进程入口、中文空格路径、新进程普通编辑保存、父窗口不变及六份真实随包样例 |
| `buttons` / `danger-buttons` | 当前 9 配色 × 明暗及按钮状态 |
| `pointer-regressions` | 跨段拖选、替换撤销、长代码、横向滑块与宽更新日志 |
| `presentation` | 正文 / 大纲 / 导图、字号、全文锚点及原窗口恢复；自生成长文与五张 HTML 表格 |
| `media-layout` | 多宽度、深浅色及多视图：长表压缩至正文宽度、短表保持内容宽度、图片比例和演示布局 |
| `performance` | 指定布局加载、首帧、就绪与内存，参数见下节 |
| `parity` / `html-tables` / `stress` | 专项样本模式，部分仍有机器环境前置条件 |

`parity` 需要预先准备对照工作区文件；`html-tables` 与 `stress` 仍依赖机器私有样本文档，不能作为干净克隆即可运行的通用门禁。通用演示与恢复优先使用 `presentation`；压力专项先核对 Program.cs 的样本前置条件，使用脱敏、可分发的数据。本次文档整理不改测试实现。

判断目标单元格是否与视口相交，不能只看控件存在；虚拟化估高会改变全文滚动比例，位置恢复需比较块与块内位置。中文 TextInput 注入不等于完整 IME 组词验证。模式入口见 [Program.cs](../scripts/ui-verification/Program.cs)。

## 5. 配置、更新和 MCP 验证

```powershell
dotnet run --project scripts/settings-verification/SettingsVerification.csproj -c Release -p:ArtifactsPath=E:/github/temp_files/vex-learning/settings-artifacts
dotnet run --project scripts/update-verification/UpdateVerification.csproj -c Release -p:ArtifactsPath=E:/github/temp_files/vex-learning/update-artifacts
```

设置验证器检查 XML 往返和部分更新。更新验证器用受控 `IUpdateService` 和启动替身覆盖 40 场景：失败重试、缺少资产 / 校验、下载、关闭恢复、重复入口、安装重试、取消、语言和释放。它不访问真实网络或运行产品安装器，真实就绪信号由安装夹具验证。

[关于专项](../scripts/about-visual-verification) 提供独立截图。MCP 用专用目录验证默认关闭、错误 Token、端口冲突、范围内外路径、确认取消、文档变化、修改同步、保存失败、审计与重启；HTTP / stdio 客户端分别联调，见 [MCP 接口](MCP接口.md)。

## 6. 性能方法

```powershell
dotnet run --project scripts/performance-verification/PerformanceVerification.csproj -c Release -p:ArtifactsPath=E:/github/temp_files/vex-learning/performance-artifacts -- E:/github/temp_files/vex-learning/performance
```

宿主自生成 12 节和 100 节文档，记录配置、初始化、即时打开、首次阅读、源码切换、返回即时及 30 次中文输入。使用独立配置和草稿 / 最近记录替身，不读取个人文档；输出 `timings.json` 与 PNG。

追加 `--profile --atomic` 细分高亮、分块、控件构造、渲染派发与布局，并使用一次载入正文和图片基址的 API。包装器只统计经过它的 Measure / Arrange 回调，零值不代表整棵树没有布局成本；子项包含在总时间内，不能重复相加。

单布局通用样本：

```powershell
python scripts/generate_stress_documents.py --output-root E:/github/temp_files/vex-learning/samples
dotnet $vexVerifier performance E:/github/temp_files/vex-learning/per-layout instant E:/github/temp_files/vex-learning/samples/Vex-01-综合语法与交互.md
```

八布局串行运行，保留源文件哈希，至少三轮并区分冷 / 热过程。首帧常含 PNG 编码，演示采样可能含固定异步等待，不能作为实体屏幕 FPS 或正式桌面冷启动。即使宿主 AOT，也只是原生离屏测量。当前数字见验收文档。

阅读渲染按块虚拟化；200 块以上的长文档及任意长度文档中的 Mermaid 块，延迟到实际量测时创建内容。短文档的其他块仍会预先构造，不能声称消除全部首次构造成本。修改此链路时需覆盖高度估算、滚动锚点、大纲跳转、图片、任务、语言与 AOT。

`UiVerification.dll mermaid <输出目录>` 使用随包图鉴验证 22 种图表 × 明暗 × 阅读/即时编辑，共 88 个组合，检查异步出图、完整缩放和无内部滚动；同时记录冷启动首帧、第一张图与重复切换耗时。性能对照应顺序运行，不和打包、测试并发，以免 CPU 竞争影响读数。

### 4.1 精细化对齐验收（2026-10-24 增）

外观与图表精细化对齐后，除上表外需追加人工目验清单（实现 ↔ 原型逐屏）：

1. 外观弹层：纸面白背景、九宫格边缘选中环完整、＋新增配色虚线块与卡片同尺寸、新增配色对话框双列紧凑布局（名称/描述紧凑行 + 浅色态/深色态并排色行）。
2. 界面密度：切档立即生效（字号/控件高/间距/圆角随档缩放），启动时按存档回放；密度令牌以 `VexDensity*` 应用资源键下发，控件样式经 `{DynamicResource}` 消费。
3. 渲染密度：排版弹层「渲染密度」只作用于 Markdown 渲染与图表（FontSize/间距/圆角联动），与外观菜单「界面密度」互不影响。
4. 导图样式弹层：卡片模式（结构/风格双页签 + 缩略线稿卡 3 列网格）、缤纷样式实色节点与粗彩线。
5. Mermaid 源码视图：阅读视图点图表或右上角 mermaid 徽标切换源码卡片（浅底/边框/等宽左对齐）；徽标不与内容重叠。
6. 新手引导卡：376px 宽、16px 圆角、无边框深阴影、顶部 6px 品牌渐变条、步进点活动 18×6 胶囊、动作行两端对齐（跳过本段/继续）。
7. 表格工具与偏好：表格三动作（复制 Markdown/CSV/预览）、偏好无页脚改值即生效、MCP 三 Tab 对齐原型。

正式可执行文件的 `--verify-runtime <临时目录>` 还会直接渲染随包图鉴的 22 个 Mermaid 样例，检查 NativeAOT 环境能输出合法 SVG；这项检查随 Windows 安装包制作执行。

## 8. 排障和完成标准

| 现象 | 先检查 |
| --- | --- |
| 应用仍使用旧库 | 中央包版本、本地源、传递包、assets 与构建目录；新版本替代覆盖同版本缓存 |
| 测试影响个人配置 | 独立 APP_CONFIG_FILE，草稿 / 最近记录替身；不能写用户笔记 |
| AOT 编译异常 | 统一 publish 脚本、本机工具链、ILC 参数；不以 JIT 结果代替 |
| 菜单 / 语言线程异常 | UI Dispatcher、离树任务、事件释放、第三方字典回退 |
| 位置恢复不稳定 | 块身份与块内位置、过期异步任务、图片布局 |
| 文档 / 原型链接失效 | 相对路径、预览路由、生成帮助数据及来源 README 哈希 |

完成一个逻辑后运行相关检查、更新文档和验证边界，检查 `git diff --check` 与产物未入库，再提交推送。真实焦点、IME、多 DPI、跨屏及系统安装另行验证；离屏不能替代。问题报告与安全约定见 [贡献与安全](贡献与安全.md)。

## 一、目标与已确认规则

1. 为应用内的普通菜单项补充 Lucide SVG 图标，顶部菜单、各级子菜单、右键菜单和工具栏下拉菜单统一使用 Lucide，不混用其他图标库。
2. 带勾选或单选状态的菜单项不添加操作图标。这类菜单项即使当前未选中，也不添加操作图标，切换状态时不得改变文字位置。
3. 统一所有菜单文字的字号，统一为 **13 个 Avalonia 逻辑像素**，在同一资源中维护；快捷键文字也采用相同字号。非菜单的面板标题、辅助说明、操作按钮和预览内容不因处于弹层中而自动归入此规则。
4. 同一操作在不同位置复用相同图标；图标颜色跟随主题、悬停、选中、禁用和危险操作状态。
5. 菜单保持现有命令、快捷键、国际化、焦点和键盘操作语义；图标不增加菜单层级，不改变菜单项顺序。

本方案覆盖应用自己绘制的菜单。操作系统提供的窗口系统菜单、文件选择对话框和系统文件管理器右键菜单受系统控制，不承诺统一其字号或图标。

文件树现有彩色 PNG 图标库、12px 树图标、24px 树行高及通栏选中样式作为既有行为保留。应用 Logo、正文图片和正文排版不纳入菜单资源改造。

## 三、显示规范

### 3.1 菜单项分类

| 类型 | 图标与状态标记 | 文字对齐规则 |
| --- | --- | --- |
| 顶级菜单入口 | 14px 单色 SVG 操作图标加文字 | 保持标题栏垂直居中，验证七组入口的总宽度 |
| 普通命令、普通子菜单入口 | 16px 单色 SVG 图标 | 下拉菜单左侧使用固定 16px 槽位，图标与文字间距建议 8px |
| 勾选型、单选型菜单 | 只显示原有勾选或单选状态，不添加操作图标 | 与普通菜单共用左侧槽位；未选中时留空，不挪动文字 |
| 最近文档等动态普通条目 | 使用统一文档图标；没有匹配图形时采用通用图标 | 文件名、快捷键和子菜单箭头分别对齐 |
| 分隔线 | 不添加图标 | 保持既有分组关系 |

勾选型和单选型按菜单语义识别，优先依据 `ToggleType` 和明确的状态类型，不以当前 `IsChecked == true` 作为唯一判断条件。普通菜单的高亮选择、键盘焦点不属于勾选状态。

禁止在同一行同时显示操作图标和勾选标记。若误为状态菜单配置操作图标，统一入口应拦截显示，覆盖验证应报告该配置问题。

当前自动配对、编辑/阅读/导图、即时/源码、侧栏、行号、字数、水印、动画、专注模式、打字机模式、全屏、置顶等状态菜单均适用此规则。外观、语言、导图样式等已有选择标记的选项也不额外增加操作图标。

### 3.2 字号与布局

- 新增统一资源 `VexMenuFontSize`，固定为 `13`。顶部入口、下拉项、级联项、右键项和快捷键均引用此资源；只有以菜单/选择项呈现的标签属于菜单文字。
- 外观、语言等文字菜单入口也纳入字号检查；不能仅在父级 `Menu` 设置字号，必须处理主题样式、局部属性及动态创建控件的覆盖。
- 使用同一既有界面字体族和字重规则。分组标题通过字重、颜色和间距区分，不再通过不同字号区分。
- 色卡、布局缩略图、正文排版卡中的真实内容预览保留预览比例和正文排版字号。布局/排版说明、面板标题、密度提示、徽标以及重置/新建/编辑/删除等操作控件不是菜单项；仅作为菜单/选择项呈现的选项名称使用菜单字号。普通设置页面和编辑正文不受菜单字号资源影响。
- 图标采用统一的方形视口、圆角线帽和线条粗细；顶部图标 14 个、下拉图标 16 个 Avalonia 逻辑像素，不以字体字符或 Emoji 替代操作图标。
- 保持现有菜单行高和浮层尺寸基线。长文字可以换行、长菜单可以滚动；新增图标不能单独撑高某一行，不能遮挡快捷键和级联箭头。
- 保留菜单项整行高亮与禁用效果。危险操作的图标和文字使用相同语义颜色，不把所有菜单图标永久着色为强调色。

### 3.3 图标语义映射

| 菜单分组或操作 | 建议 SVG 语义 |
| --- | --- |
| 文件入口；新建、打开、最近、保存、另存为 | 文件；新建文件、打开文件/文件夹、历史、保存、另存 |
| 导入、导出及格式子项 | 导入/导出方向箭头；HTML、PDF、图片、文档类型图形 |
| 打印、属性、打开位置、编码重开、删除、关闭 | 打印机、信息、定位文件夹、文本编码、垃圾桶、关闭 |
| 编辑入口；撤销、重做、剪切、复制、粘贴、全选、查找、替换 | 编辑；方向箭头、剪刀、复制页、剪贴板、选区、放大镜、替换 |
| 段落入口；正文、H1～H6、列表、引用、代码、公式 | 段落；正文段落、标题等级、对应列表、引用、代码、数学公式 |
| 表格及行列操作 | 表格；带行列方向、插入、删除、对齐语义的变体 |
| Mermaid 及其模板 | 图表入口和图表类别图形；确无适合图形时使用统一图表图标 |
| 格式入口；粗体、斜体、删除线、高亮、上下标、链接、图片、清除格式 | 格式；对应文本格式、链接、图片、清除格式图形 |
| 视图、工具、帮助入口及其普通命令 | 面板、工具、帮助；按布局、统计、分享、MCP、引导、更新、反馈等操作映射 |
| 文件右键中的路径、刷新、新窗口、重命名等 | 复制路径、刷新、新窗口、重命名；与其他菜单同义操作复用 |

上表是分配规则；实施前生成逐项清单，覆盖全部普通菜单项。导出格式图标和动态文档图标也使用菜单 SVG 资源，不依赖文件树 PNG 库。

### 3.4 样板交付

准备新建、打开文件夹、保存、复制、查找、表格、导出、删除等代表性图标样板，同时展示“普通图标项、已勾选项、未勾选项”的对齐关系。样板只呈现图标及必要标签，不制作整套界面效果图；随实施检查 14/16 个 Avalonia 逻辑像素、明暗主题及线条清晰度。

## 四、资源与实现安排

### 4.1 SVG 源文件与原生矢量资源

1. 在 `src/Vex/Assets/MenuIcons` 集中维护 SVG 源文件，统一采用同一版本的 Lucide 线性图标。实施时固定具体发布版本及对应提交 SHA，记录每个文件的上游路径和本地修改，只纳入实际使用的图标，不持续跟随 `main` 分支下载。
2. 使用仓库已有 Node.js 脚本体系添加确定性转换脚本，将受支持的 SVG 转换为 Avalonia 原生矢量资源，生成 `src/Vex/Styles/MenuIcons.axaml`。源文件修改时显式生成，并在验证时检查产物是否过期。
3. 生成资源随源码入库，普通 `dotnet build` 不额外要求安装 Node.js。运行时使用原生矢量资源，不通过 `Bitmap` 加载 SVG，也不将 SVG 预先栅格化为 PNG。
4. 转换器明确支持范围：统一视口、路径、基础线段/圆形/矩形等经规范化后输出路径，保留多路径、描边和填充语义。无法保真的复杂 SVG 直接报错，不能默默丢失变换、裁剪、渐变等内容；优先调整所选图标源文件。
5. 单色图形的颜色由主题资源提供，不能将 SVG 中的黑色硬编码到生成产物。状态勾选与单选标记继续承担状态表达，不需要注册为普通菜单图标。

上游仓库：[lucide-icons/lucide](https://github.com/lucide-icons/lucide)；图标预览：[Lucide Icons](https://lucide.dev/icons/)；许可说明以所固定版本的 `LICENSE` 为准。当前许可为 ISC，并包含部分继承自 Feather 的图标所需的 MIT 声明；引入时完整保留上游版权与许可证文本，在资源来源清单和应用鸣谢中记录。

Lucide 没有精确对应图形时，优先选用同库中语义最接近的图标；确需调整时基于 Lucide 做最小修改并记录，不临时混入其他库。逐项映射必须核对固定版本的真实图标名称，不假定历史名称或别名对应独立 SVG 文件。

这是 SVG 源资源配合原生矢量渲染的方案。若实施中发现转换无法保真，应先记录具体图标、原因及同库替代图标，再调整资源处理方式。

### 4.2 公共组件与职责

| 位置 | 计划职责 |
| --- | --- |
| `src/Vex/Assets/MenuIcons` | SVG 源文件、来源清单和许可 |

| `src/Vex.Controls/Themes/Controls/Menu.axaml` | 统一字号、图标槽、勾选槽、快捷键、箭头与交互状态样式 |
| `src/Vex.Controls/Themes/Controls/TitleBar.axaml` | 检查顶级菜单和标题栏既有资源样式是否参与字号/图标呈现；按实际归属决定是否改动 |
| `src/Vex` 中的菜单图标分配入口 | 普通菜单语义 ID 到资源键的映射、状态项排除，供 XAML 与动态菜单共同使用 |

资源键使用稳定语义，如 `MenuIcon.Save`、`MenuIcon.Copy`、`MenuIcon.TableRowAbove`，不能依赖中文或其他语言的显示文本。重复命令依据动作参数区分，如 H1/H2、表格行列操作和导入/导出格式。

共享不可变矢量数据，各处创建独立图标控件实例，不能将同一个控件实例挂到多个菜单。图标不抢焦点、不单独参与点击，菜单文字继续承担可访问名称。

### 4.3 模板与弹层覆盖

- 顶部自定义模板按 Avalonia/现有菜单实际契约接入图标，左侧固定槽按菜单语义互斥显示操作图标或状态标记。右键 `ContextMenu`、`MenuFlyout` 和动态菜单需分别确认其模板、样式类与视觉树；不能假设顶部 `design-menu-entry` 模板或其资源会自动覆盖其他菜单。各类文字字号和图标颜色在各自呈现宿主中复用同一资源与语义入口，并验证独立视觉树中的资源解析。
- 动态菜单使用同一个分配入口，不能另建一套图标和硬编码字号。
- 外观、语言、导图样式等选项保留现有选择标记；选项文字纳入统一菜单字号。布局/排版内容画廊只检查可选项名称，不把说明、面板标题、徽标、面板工具按钮和真实内容预览强行改成菜单字号；颜色选择器不纳入菜单项图标范围。
- 不直接修改全局 `TextBlock` 或通用 `Button` 字号。采用菜单专用资源和样式类，避免改变正文、设置页、工具栏非菜单按钮和其他窗口。
- 顶级菜单新增图标后，验证紧凑窗口及四种语言的可用宽度；在既有支持尺寸内不得遮挡外观、语言、搜索和窗口按钮。如出现溢出，记录尺寸与语言后调整菜单布局，不擅自缩小字号或隐藏文字。

## 六、验收标准

| 场景 | 通过标准 |
| --- | --- |
| 菜单覆盖 | 清单中的普通菜单项均使用 Lucide SVG 来源的矢量图标，不混用其他图标库；新增入口不能遗漏动态菜单和级联子项 |
| 状态菜单 | 勾选/单选项不配置且不显示操作图标；选中时只显示状态标记，未选中时保留空槽，文字无位移 |
| 字号 | 顶级、下拉、级联、ContextMenu、MenuFlyout 和快捷键文字的最终字号均为统一资源值 13；面板说明、徽标、工具按钮、布局/排版描述与真实预览属于非菜单控件并保留各自类型 |
| 资源与复用 | 同义操作共享相同矢量定义，控件实例不共享父级；资源和映射完整，来源许可齐全，无联网下载图标依赖 |
| 明暗及交互状态 | 图标与文字的主题和状态一致，危险色清晰，禁用可辨识，无黑色图标在深色背景中消失的问题 |
| 布局与缩放 | 图标清晰、不拉伸、不撑高单行；文字、快捷键和箭头不重叠；顶部七组入口不遮挡相邻功能 |
| 菜单行为 | 点击、方向键、Enter、Esc、快捷键和勾选行为保持正确；源码与即时编辑右键操作仍针对正确内容 |
| 回归边界 | 文件树图标、选择、行高以及正文/设置字号无无关变化；实际平台验证与未验证范围均有记录 |

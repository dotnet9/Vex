# 安装与发布

本文合并版本发布、Windows 安装维护、Linux 元数据和 macOS DMG 说明。使用者安装步骤见 [快速开始](快速开始.md)，开发联调见 [开发与验证](开发与验证.md)。以下命令是维护流程，不表示仅阅读文档就应执行产品安装、卸载或创建发布标签。

## 1. 版本和交付矩阵

版本唯一来源为 [Directory.Build.props](../Directory.Build.props) 的 Version。正式标签为 `v<版本>`，README、根 UpdateLog 和发布说明同步。安装器只消费已发布目录中的载荷，不读取相邻库源码。

| RID | 载荷与工具 | 正式安装包名 |
| --- | --- | --- |
| win-x64 | NativeAOT + Inno Setup 6 | `Vex-v<版本>-win-x64-setup.exe` |
| linux-x64 | 原生 x64 runner + dpkg-deb | `Vex-v<版本>-linux-x64.deb` |
| linux-arm64 | 原生 arm64 runner + dpkg-deb | `Vex-v<版本>-linux-arm64.deb` |
| osx-x64 | Intel macOS + hdiutil / Finder | `Vex-<版本>-osx-x64.dmg` |
| osx-arm64 | Apple Silicon macOS + hdiutil / Finder | `Vex-<版本>-osx-arm64.dmg` |

每包附 `.sha256`，Release 只交付这五包和五个校验文件，不发布 ZIP、win-x86 或开发符号作为安装包。macOS 文件名没有版本前缀 `v`，不能套用 EXE / DEB 命名。

## 2. 本机 NativeAOT 载荷

```powershell
pwsh scripts/publish.ps1 -RuntimeIdentifier win-x64 -ArtifactsRoot E:/github/temp_files/vex-release/artifacts -PublishRoot E:/github/temp_files/vex-release/publish/win-x64
```

[publish.ps1](../scripts/publish.ps1) 接受 RuntimeIdentifier、Version、ArtifactsRoot、PublishRoot、RuntimeFrameworkVersion、NativeCompilerTargetsPath。Version 默认从中央构建文件读取；Windows 使用 net10.0-windows，其他平台使用 net10.0。

统一开启 PublishAot / PublishTrimmed，关闭 PublishSingleFile，保留完整类型元数据，设置 IlcSingleThreaded=true、IlcUseServerGc=false。后两项约束编译器，不代表应用 GC 或运行线程策略。macOS StripSymbols=false 处理工具链调试段限制，最终安装包仍剔除独立开发符号。

Windows 需本机 C++ / Windows SDK 与 Inno Setup；Linux 需 clang、zlib1g-dev、dpkg-deb；macOS 需 Xcode 命令行工具、hdiutil、可用 Finder 会话与自动化权限。各架构使用对应原生 runner，不把 Windows 构建契约当成 Linux / macOS 的交叉 AOT 成功。

运行时和 PE 验证：

```powershell
pwsh scripts/verify_native_publish.ps1 -ExecutablePath E:/github/temp_files/vex-release/publish/win-x64/Vex.exe -OutputPath E:/github/temp_files/vex-release/native.json
```

正式可执行文件还支持 `--verify-runtime <独立目录>` 检查版本、四语、对话框资源与隔离配置。若本机 ILC 崩溃，可按脚本参数指定已安装的运行时和 compiler targets；不要以托管启动结果代替 AOT 检查。

## 3. Windows 生产入口和维护

[scripts/Vex.iss](../scripts/Vex.iss) 包含本仓 [Vex.Setup.iss](../scripts/installer/Vex.Setup.iss)。界面为 640×360、左侧 180px 品牌区、墨青 `#24766B`、单主标题，支持简体中文 / 英文和明暗主题；安装目录和两个默认选中的选项折叠展示，MIT 完整原文可滚动。生产引擎负责取消、占用、回滚与完成启动。

```powershell
& 'C:/Program Files (x86)/Inno Setup 6/ISCC.exe' scripts/Vex.iss /DAppVersion=1.7.0 /DSourceDir=E:/github/temp_files/vex-release/publish/win-x64 /DOutputDir=E:/github/temp_files/vex-release/packages
```

当前为当前用户安装。Markdown 选项统一控制候选、图标与右键入口，不写 Windows UserChoice、不强制默认。应用启动尊重未勾选的选择。维护只识别自身精确 AppId 和已验证的注册卸载器；修复复用正常安装，卸载交给系统原生确认和进度。主程序缺失时禁用打开；未知位置和迁移状态避免提供无效重叠操作。

检测旧全用户安装时先确认移除，按已注册卸载器请求管理员权限；取消、UAC 拒绝、卸载失败或残留注册均阻止复制新载荷。迁移前备份旧 Vex.exe.config / Vex.dll.config 到 `%LOCALAPPDATA%\Vex\MigrationBackup`，恢复遵循已有目标配置优先规则；备份不记入卸载日志。只依赖旧安装器的精确文件日志清理，不递归清空旧目录或删除用户自放文件。

品牌资源由 `node scripts/installer/render-brand.cjs` 使用 sharp 从 SVG 生成离线 BMP；正式编译无需 Node 或联网。共享 `CodeWF.Setup.*` 紫色引擎仍作为来源快照保留，Vex 正式产品使用专用绿色外观。32 位 Inno 引擎 ABI 与 x64 产品载荷是不同概念，升级编译器后要运行原生夹具。

### 契约、维护和视觉验证

```powershell
pwsh scripts/tests/windows_setup_contract_test.ps1
pwsh scripts/tests/windows_setup_contract_test.ps1 -Compile -InnoSetupCompiler 'C:/Program Files (x86)/Inno Setup 6/ISCC.exe'
python scripts/installer/tests/verify_maintenance_logic.py --compiler 'C:/Program Files (x86)/Inno Setup 6/ISCC.exe' --output E:/github/temp_files/vex-release/maintenance
python scripts/installer/tests/verify_vex_migration.py --compiler 'C:/Program Files (x86)/Inno Setup 6/ISCC.exe' --output E:/github/temp_files/vex-release/migration
pwsh scripts/installer/tests/verify_vex_visual.ps1 -Compiler 'C:/Program Files (x86)/Inno Setup 6/ISCC.exe' -Output E:/github/temp_files/vex-release/visual
```

维护逻辑为 3 个夹具各 57 项、合计 171 断言；迁移 49 项。预处理检查排除真实注册 API、ShellExec、Exec、外部函数和安装声明，InitializeSetup 返回 False。生产分支另做编译，确认真实逻辑未被测试替身替换。纯逻辑夹具只写报告，不执行真实卸载。

视觉夹具在独立 desktop 中使用真实 Inno 窗口，不切换用户桌面，可在锁屏时运行。只复制 LICENSE，不建真实产品注册、快捷方式，不启动 Vex 或卸载器；覆盖中英文、明暗、新装、设置、许可、进度、完成、维护、缺失程序、未知位置、多作用域和迁移。使用新的仓外输出目录，按持有句柄清理测试进程。

需要参考图时给 `verify_vex_visual.ps1` 追加 `-ReferenceDirectory <原型截图目录>`。`compare_vex_visual.py` 计算 `100 × (1 − RGB 平均绝对误差 / 255)`，同时输出原始 RGB 与两图 1px 高斯容差指标；容差门槛 98%。只排除窗口外角落及机器相关路径，控件边缘和交互另验。该数值仅覆盖指定状态，不能推导全应用、多 DPI、系统对话框和其他平台均达 98%。

## 4. Linux DEB 与元数据

[package_linux_deb.ps1](../scripts/package_linux_deb.ps1) 消费 SourceDirectory，生成对应 amd64 / arm64 包：

```powershell
pwsh scripts/package_linux_deb.ps1 -RuntimeIdentifier linux-x64 -Version 1.7.0 -SourceDirectory /tmp/vex-release/publish/linux-x64 -OutputDirectory /tmp/vex-release/packages -Force
```

上述路径在 Linux 上替换为实际仓外临时目录。包包含可执行文件、语言 / 帮助资源、hicolor PNG、scalable SVG、desktop 文档类型声明、MIT、Homepage 和 AppStream。描述在 [product.json](../scripts/installer/linux/product.json) 维护，生成脚本来源与摘要在同目录 source.json。

AppStream branding 使用品牌绿色；软件管理器是否采用颜色及其授权、安装、移除窗口由发行版决定。不能通过 DEB 统一替换系统皮肤，也不引用未发布的宣传截图。

`pwsh scripts/tests/linux_metadata_test.ps1` 验证元数据和图标；`pwsh scripts/tests/linux_packaging_test.ps1` 覆盖双架构暂存、启动、符号剔除、体积、校验和与失败传播。Windows 为受控打包边界，Linux 有 dpkg-deb 时调用真实工具。实机仍需 `appstreamcli validate`、安装 / 移除和软件管理器检查。

## 5. macOS app、DMG 与设备清理

[package_macos.sh](../scripts/package_macos.sh) 将已发布载荷组为 app 并制作 DMG，底层调用仓内 `installer/macos/create-branded-dmg.sh`。示例在对应 macOS 架构执行：

```bash
PUBLISH_ROOT=/tmp/vex-release/publish ARTIFACTS_ROOT=/tmp/vex-release/macos bash scripts/package_macos.sh osx-arm64
```

脚本接受 osx-x64 / osx-arm64 / all；PUBLISH_ROOT 下保持各 RID 的 Vex 载荷目录。未设置 CODESIGN_IDENTITY 时为 ad-hoc，Developer ID、ENTITLEMENTS、NOTARIZE=1 与 NOTARY_KEYCHAIN_PROFILE 按真实签名配置启用；不要从脚本支持推断当前包已经公证。

Finder 窗口 740×436，背景 740×406，图标 88 点；应用 / Applications 坐标 (235,220) / (505,220)。背景包含白纸、左下淡绿、箭头和完成提示；复制、覆盖与权限由 Finder 处理。默认中英双语，打包时 `CODEWF_DMG_LANGUAGE=bilingual|en|zh`；静态背景无法在用户挂载时自动切语。

品牌层用 hdiutil 创建 HFS+ 可写镜像，osascript 配置 Finder，再转换 UDZO 并验证。挂载 plist 必须解析出唯一整盘设备；按设备正常 detach。正常卸载及 EXIT 清理各最多五次，间隔 1 / 2 / 4 / 8 秒；不强制卸载、不结束 Finder。若报错后状态检查证实已分离才继续，状态不可解析或持续占用则终止、保留临时目录和路径，避免删除仍挂载的文件。

背景维护运行 `node scripts/installer/macos/render-backgrounds.cjs`（需 sharp），更新三语言 PNG / SVG 及来源摘要；正式打包只读离线 PNG。受控检查：

```bash
bash scripts/installer/macos/tests/branded-dmg-test.sh
bash scripts/tests/macos_packaging_test.sh
```

受控替身覆盖语言、资源、参数、临时占用、设备状态、解析失败、清理及挂载 / 布局 / 转换 / 验证失败传播，不操作本机 Finder。真实发布仍需 macOS 交互会话检查挂载、Retina、多屏、Gatekeeper、公证及安装后启动。

## 6. 来源快照与文档例外

Windows 和 macOS 的 source-sha256.json 记录共享来源与 Vex 本地覆盖；文本按约定 LF，位图按二进制。Windows 清单固定 14 个文件，禁止删除清单项或改哈希模式绕过来源检查。改变本地来源 README 时只更新对应摘要和本地说明，不冒充未改的上游文件。

两个安装目录的 README 保留为短导航，因为属于来源契约；正文集中在本文。第三方 LICENSE、NOTICE、OFL、语言文件头署名及来源清单留在资源附近。Inno 简体中文文件由 Zhenghan Yang 维护，来源为 [官方翻译](https://github.com/jrsoftware/issrc/blob/main/Files/Languages/ChineseSimplified.isl)，随 [再分发许可](../scripts/Languages/INNO-SETUP-LICENSE.txt) 一同维护。

## 7. 正式发布顺序

1. 完成开发、更新需求 / 设计、版本与 UpdateLog，选择相关验证和当前系统原生门禁，明确尚未实机验证的边界。
2. 自研库先用本地新版本包验证；完成后更新正式版本并推库标签，等待同版本 NuGet 可还原。
3. Vex 中央包固定正式版本，完成收尾验证，按逻辑中文提交推送 main。
4. 将发布说明写为仓外 UTF-8 文本，以附注标签创建版本，再推送对应标签：`git tag -a vX.Y.Z -F <说明文件>`、`git push origin vX.Y.Z`。不移动已发布标签。
5. [release.yml](../.github/workflows/release.yml) 实际顺序为 Windows 安装器编译 / 迁移预检 → 五架构原生 publish / package → 产物聚合校验 → 创建 Release。它不是整套应用测试自动先行，必要回归需提前完成。
6. 检查 Release 正文、五包与五 SHA，实际下载再校验，补充平台实机结果。

说明优先级：`.github/release-notes/vX.Y.Z.md` 精选正文 → 远端附注 tag 内容 → UpdateLog 精确版本段；缺失有效说明时失败。修正现有 Release 正文可更新精选说明或手动运行同步工作流，不改变资产和标签。相关独立检查还包括更新、安装契约、打包契约、NuGet 发布及文档通知工作流。

校验聚合目录必须只包含当版五包和五份 SHA：

```powershell
pwsh scripts/verify_release_installers.ps1 -Version 1.7.0 -PackageDirectory E:/github/temp_files/vex-release/packages
```

公开下载校验通过不等同所有系统安装 UI 完成验收。1.7.0 正式证据、SHA 和未验边界见 [验收与已知限制](验收与已知限制.md)。

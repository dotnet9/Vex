## 第一档（素材最全、受众最广）

### 1. Markdown 编辑器每键 22× 提速：脏块回写替代全文序列化

- slug: `vex-editor-dirty-block-writeback`
- 简述：每次打字把整篇 Markdown 序列化一遍再回抛，大文档下卡到没法用。改为只重算被编辑的脏块片段，拼回缓存全文——实测 229KB 文档每键 1.76ms 降到 0.08ms，内存分配降 14×。顺带发现编辑器的性能瓶颈不在解析端（很多人第一反应），而在回写端。

### 2. 流式 Markdown 渲染：冻结前缀 + 尾部容错，逐 token 追加 42× 提速

- slug: `vex-streaming-markdown-frozen-prefix-remend`
- 简述：AI 时代逐 token 输出 Markdown 是热门场景，但每次追加都整篇重新解析，20KB 文档跑一遍要 1.3 秒、2.5GB 内存分配。方案：冻结边界之前的内容解析一次永不重算，尾部容错补全（借鉴 vercel/streamdown 的 remend 思路但不跟它的实现），实测 42× 提速、内存降 24×。附冻结边界规则表和等价性测试设计。
- ⚠️ 数字注意：基准已迁入本仓按 .NET 11 重测，新口径为 **47×（等价场景 177×）/围栏 70×**，旧 42×/60× 是外仓口径——写作时以新基准为准。

### 3. Avalonia 跨块文本选择：渲染层的选择控制器怎么做

- slug: `vex-cross-block-text-selection`
- 简述：Avalonia 的 SelectableTextBlock 只支持单块内选择，渲染后的 Markdown 跨段落、跨列表、跨代码块拖选会断。自写一个 328 行的选择控制器，解决跨块选区连续性、虚拟化回收后的选区保留、以及被虚拟化移出的块也能复制的问题。

### 4. Markdown 编辑器的块编辑状态机：muya 模型的 C# 实现

- slug: `vex-block-editor-state-machine-muya`
- 简述：Typora/muya 的即时编辑核心是一个块级状态机：回车拆块、退格合并、块首标记转换（# 空格变标题）、列表 Tab 缩进、围栏补全。把它做成纯逻辑层（不依赖 UI），49 个单测覆盖键盘矩阵。聊设计决策和踩过的键盘事件坑（IME 下 Key.ImeProcessed 归一化等）。

### 5. 用 Avalonia 复刻 GitHub Desktop 的 Git 面板：分支管理、状态徽章与四态同步按钮

- slug: `vex-git-panel-github-desktop`
- 简述：桌面 Markdown 编辑器内置 Git 面板，照着 GitHub Desktop 的交互逐项复刻：同步按钮随仓库状态换动作（发布/推送/拉取/获取四态）、分支下拉带筛选与三组分组（默认/最近/其他）、新建/切换/重命名/删除确认/合并到当前分支、文件树挂 Git 状态徽章（前导状态槽 + octicon + 行级增删统计）。素材三轮迭代全在（V2.2.0.0~2.2.1.0），附 LibGit2Sharp 在 AOT 下的坑和网络操作移出 UI 线程的冻结修复。（V2.2.2.0 新增候选）

### 6. 虚拟化的反例：长文档阅读为什么把虚拟化关了

- slug: `vex-reading-full-layout-virtualization-off`
- 简述：虚拟化是长列表的性能标配，但在 Markdown 阅读场景成了 bug 温床：窗口判定按估高计算，延迟建块和图片加载让视口漂移，「滚动出现空白带」「点击正文视口上移」接连出现。最终决策：普通文档默认全量量测排列，虚拟化只在超长流式文档显式开启。附三个点击跳动的根因链（空白点击拽末段/揭示块拽动/预览吸顶）和一个真实案例——升级架构后 UiVerification 的断言还停在旧架构，被发布门禁当场拦下。（V2.2.2.0 新增候选，已用户实测验收）

## 第二档（Avalonia 深水区，适合系列化）

### 7. Avalonia 块拖拽排序：把手、指示线、撤销一步到位

- slug: `vex-block-drag-reorder`
- 简述：Notion 式块拖拽在 Avalonia 里没有现成方案。从拖拽把手（悬停显示）到指针循环（插入指示线跟随）到落位重排（撤销可回），三个环节逐个讲。附带讲 NativeAOT 下 Avalonia 控件的指针事件坑。

### 8. .NET NativeAOT 桌面程序的文件监听：FileSystemWatcher 在 AOT 下不能用怎么办

- slug: `vex-nativeaot-file-watcher-fingerprint-polling`
- 简述：NativeAOT 下 FileSystemWatcher 事件管线存在随机无栈 NRE（fail-fast，无托管栈），只好禁用。禁用后文件树不刷新——加指纹轮询兜底（文件数 + 最新 LastWriteTime），稳态零开销，变更才触发缓存失效。聊 FileSystemWatcher 在 NativeAOT 下的坑和替代方案。

### 9. Avalonia 应用三档密度：一个令牌引擎管 80 个控件的字号/间距/圆角

- slug: `vex-density-token-engine`
- 简述：紧凑/正常/宽松三档 UI 密度切换，80+ 令牌（字号、控件高、间距、圆角、行高）统一由密度引擎批量写入应用资源。聊令牌设计、密度联动 80 项回归怎么过、以及哪些控件绕过了令牌体系（踩坑）。

### 10. Avalonia 排版主题系统：13 套文章排版的设计与实现

- slug: `vex-typography-theme-system`
- 简述：13 套文章排版主题（字号/行高/对齐/边框/装饰色/间距），每套标题的居中或居左由主题数据决定。聊主题数据结构（ArticleTypography）、资源分发链（从注册到渲染器的绑定路径）、以及标题对齐随主题切换的实现。

### 11. Avalonia 12.2 升级列车三坑实录：从 NU1301 玄学到类型加载崩溃

- slug: `avalonia-12-2-upgrade-train-pitfalls`
- 简述：依赖列车一次踩三个互不相干的坑：①NuGet 还原报「127.0.0.1:55802 拒绝连接」——网络全通唯独 restore 不通，真凶是常驻 MSBuild 节点残留旧代理环境，`dotnet build-server shutdown` 一条命令根治；②本地候选包 12.2.0.1 缺源时被 NU1603 飘升顶替成 nuget.org 上废弃版本线的 12.2.1，XAML 编译直接炸；③Svg.Skia 的传递依赖把 Avalonia.Skia 拽在 12.0.0 地板版，与 12.2.0 混装出 TypeLoadException。可合写也可拆三篇。（V2.2.2.0 新增候选）

### 12. 长文档滚动定位：前缀索引 + 二分查找替代线性扫描

- slug: `vex-long-doc-scroll-prefix-index`
- 简述：几千块的文档里把滚动偏移换算回块序号，线性扫描每次拖动都是 O(n)。改为块高前缀索引 + 二分定位，长文拖动滚动条更跟手。（V2.2.2.0 新增候选）

### 13. 大图不再卡正文：图片后台解码与远程缓存统一失效

- slug: `vex-image-background-decode-remote-cache`
- 简述：图片解码默认在 UI 线程，大图一加载整篇卡住。改后台解码 + 就绪重排补绘，远程图片缓存失效收口统一入口。（V2.2.2.0 新增候选）

### 17. 设计原型像素对照：HTML 原型到 Avalonia 实现的 97.94% 一致性门禁

### 18. NuGet 还原玄学排障：MSBuild 常驻节点里的旧代理

- slug: `nuget-restore-1301-msbuild-node-proxy`
- 简述：restore 报「127.0.0.1:随机端口 拒绝连接」，但 curl/PowerShell/python 全通、代理环境变量是空的、系统代理也是关的——网络排查全部死胡同。真凶：常驻 MSBuild worker 节点复用了几小时前带代理环境的会话，`dotnet build-server shutdown` 一条命令根治。附排除法全过程。（V2.2.2.0 新增候选）

### 19. 本地全绿，CI 红了：跨仓契约门禁抓 AI 手改生成物

- slug: `cross-repo-contract-check-catches-ai-generated-drift`
- 简述：AI 协作开发的新坑：AI 为加几个界面文案直接手改四语言 JSON 和生成代码，本地构建全绿——因为跨仓契约 `--check` 只在 CI 跑。漂移到下一次 CI 才现形。聊契约门禁的设计（生成物禁止手改、源头在 design/assets、--check 比对）和这次连红的修复。（V2.2.2.0 新增候选，AI 协作题材）

### 20. NuGet 影子包新变体：本地候选被废弃版本线的正版飘升顶替

- slug: `nuget-shadow-package-elevation-nu1603`
- 简述：本地候选包 12.2.0.1 只在本地源，nuget.org 上还挂着历史废弃线的 12.2.1——依赖解析遇到缺源直接飘升顶替（NU1603 警告），编出来的是"影子包"。聊 NU1603 的触发条件、为什么精确版本也会中招、unlist 与删包的语义差异、以及 packageSourceMapping/升版本号两种解法。可与《NuGet 还原玄学排障》合写。（V2.2.2.0 新增候选）

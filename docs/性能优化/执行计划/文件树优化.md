当前状态：用户已于 2026-10-24 确认开始实施。Step 1–4 和 Step 5 的离屏／结构性验证已完成；实际桌面窗口交互、Linux/macOS 实机及虚拟化成本仍待验证。打开文件夹时根目录默认展开、所有子目录默认折叠，只显示一层直属内容。单击展开、图标、通栏选中及布局调整作为回归基线。

## 一、目标与范围

1. 首次打开工作区只枚举根目录直属内容，不扫描全部后代，不批量读取文档摘要。
2. 打开文件夹时根目录默认展开，所有子文件夹默认折叠，只显示根目录直属内容；首次展开子文件夹时，异步读取它的直接子级，继续保持下一级文件夹折叠。
3. 复用已加载节点；有效缓存再次展开不读盘，失效缓存只重载受影响目录。
4. 以工作区为范围监听文件变化，按受影响目录增量更新，补齐直接打开文件时的父目录监控。
5. 搜索、平铺列表、快速打开和 MCP 文件清单仍覆盖整个工作区，不受树中哪些目录已展开的影响。
6. 工作区切换可以取消后台任务，旧工作区和旧目录快照不得覆盖当前状态。
7. 监控到当前文档变化时通知界面，按第 4.6 节保护流程重新读取和载入；编辑器、阅读视图和预览共享同一份正文，未确认的磁盘版本不覆盖编辑内容。

本次实施不涉及分支调整、提交推送、启动和发布脚本、图标资源替换，也不扩大可编辑文档类型；继续支持 `.md`、`.markdown`、`.mdown`、`.txt`。

| 没有工作区取消、过期结果拒收及监控溢出恢复 | `MainWindowViewModel` 文件夹监控链路 | 增加工作区代次、目录修订号、取消令牌及 Error 恢复 |

| 批量折叠可能逐节点同步写配置 | `ShellFilesViewModel` 展开通知、`AppSettingsStore.Update` | 批量操作只保存一次配置，初始化采用根展开、子目录折叠规则 |

## 三、建议确认的交互约定

以下约定作为本方案建议的默认实施口径，确认方案时一并确认。

| 场景 | 目标行为 |
| --- | --- |
| 层级定义 | 工作区根为第 0 层，根的直属文件和文件夹为第 1 层，子文件夹的直属内容为第 2 层 |
| 首次打开文件夹 | 立即显示、选中并聚焦根节点，根默认展开；后台只枚举第 1 层并显示，所有子文件夹保持折叠，不检查子目录内部；读取未完成时显示加载状态 |
| 单击根节点 | 在展开与折叠之间切换；再次展开时，第 1 层缓存有效则直接显示，读取未完成则复用已有任务，不重复发起读取 |
| 首次展开子目录 | 只枚举该目录的直接子级，不预读孙目录，不为判断箭头而扫描后代 |
| 再次展开 | 缓存有效时直接显示；有变更标记时重新读取该目录 |
| 空目录、仅有非文档文件的目录 | 显示非点目录本身；展开后若无可展示内容则显示为空。此项会让以前因没有支持文档而被遗漏的目录可见 |
| 点目录 | 继续隐藏名称以 `.` 开头的子目录及后代；显式打开的点目录根仍可使用；普通点文件按支持扩展名判断 |
| 首篇文档 | 根目录直属存在支持文档时，按既有排序自动打开首篇；只有深层文档时不递归寻找，保留当前编辑内容，等待用户展开选择 |
| 演示文档、启动指定文件 | 沿用明确指定的文档路径；不以递归全量扫描作为打开前置条件 |
| 当前文档在未加载目录中 | 保留当前文档状态，不因索引或目录刷新主动展开整条路径；用户主动定位结果时才逐层加载并定位 |
| 刷新与重新打开 | 同一工作区刷新保留用户手动展开或折叠状态及可保留的选择，不强制重新展开根目录；重新打开工作区时重置为根展开、所有子目录折叠，不恢复上次的子目录展开状态 |
| 全部折叠 | 显式操作时允许连同根目录一起折叠；仅在重新打开工作区时恢复根默认展开 |
| 选中节点被删除 | 导航选择回退到最近仍存在的父目录；当前编辑内容交由现有文档保护处理，不自动打开另一篇文档 |

继续保留 12px 图标、24px 行高、5px 左右边距、搜索框对齐、通栏选中背景和已确认的全部折叠图标。加载或错误提示不应撑大正常树行。

## 四、职责与数据流

### 4.1 目录树与路径索引分离

- **目录树**：只持有已读取目录的直接子节点；负责导航、展开、选择和目录缓存。
- **路径索引**：只记录支持文档的路径、名称和相对位置；在首次使用搜索、平铺列表、快速打开或 MCP 清单时递归建立，不打开文件读取摘要。
- **摘要缓存**：仅在平铺列表项目进入显示范围或文件提示实际打开时读取；按路径和文件变更修订缓存，内容变动后失效。

路径索引不在普通树首开后自动全速扫描。需要完整结果的功能会明确显示加载状态，扫描完成后才显示完整结果或“无匹配项”；快速打开可先展示最近文件，再补充工作区候选。

当前侧栏实际按文件名筛选，快速打开按名称和路径筛选；保持这些语义，不因代码中的旧摘要注释额外增加全文或摘要搜索。

### 4.2 组件安排

| 组件 | 职责 | 边界 |
| --- | --- | --- |
| Core 中的目录条目、加载状态和工作区服务契约 | 描述路径、目录与文件类型，以及单层枚举、路径索引和刷新通知 | 不引用 Avalonia、不解码图片、不进行界面调度 |
| `WorkspaceFileService`，位于 Workspace/Services | 管理工作区会话、单层读取、目录缓存和按需路径索引 | 复用现有文件枚举和文档类型判断，不扩展成通用文件管理框架 |
| `WorkspaceFileMonitor`，位于 Workspace/Services | 包装一个工作区级 FileSystemWatcher，过滤、合并并输出受影响路径 | 随工作区释放；不为每个文件夹创建监控器，不直接改 UI 集合 |
| `DocumentFileFactory` | 创建轻量文档信息，提供受限摘要读取 | 保留现有摘要长度上限；普通目录枚举不读取正文 |
| `ShellFilesViewModel` 与 `DocumentFileNode` | 管理展开状态、稳定节点实例、集合差异和选择恢复 | 所有可观测集合及绑定属性在 UI 线程更新 |
| `MainWindowViewModel` | 协调打开工作区、打开文档、未保存确认及当前文档保护 | 移出目录扫描和监控调度细节，避免继续堆入主 ViewModel |

实施时按现有依赖注入注册服务。只有被多个生产调用方或验证替身使用的边界才增加接口；文件名和方法签名以最终调用关系为准。

### 4.3 子节点加载状态

节点区分 `NotLoaded`、`Loading`、`Loaded`、`Failed`，同时记录缓存是否失效。

1. 未加载的文件夹保留展开入口。若 Avalonia 模板必须依赖子项才显示箭头，使用专用占位项；占位项不能参与文件打开、搜索、排序和右键路径操作。
2. 工作区初始化时根节点默认展开，启动根目录的单层加载；子目录仅在首次展开时启动单次加载任务，重复触发复用该任务。目录枚举和排序在后台执行。
3. 完成后在 UI 线程应用子节点差异；同路径节点尽量复用，新增目录默认折叠。
4. 加载途中收起目录不自动重新展开它；结果仍属于当前目录修订时可缓存。切换工作区、移除目录时取消对应任务。
5. 读取失败保留可重试入口；错误不伪装成成功读取后的空目录，自动监控刷新也不反复弹窗。
6. 索引和目录读取均采用受限并发、分批通知；不为每个文件或目录启动一个无界任务。

### 4.4 监控和增量刷新

保留一个 `IncludeSubdirectories=true` 的工作区级监控器。监控器由操作系统报告变化，不代表应用需要递归枚举并建立所有树节点。

| 事件 | 处理方式 |
| --- | --- |
| 支持文档新增、删除 | 合并到对应父目录；更新已存在路径索引，失效相应摘要 |
| 支持文档内容修改 | 更新该文件元数据并失效摘要；不重建整个目录结构；当前文档通知和正文载入按第 4.6 节处理 |
| 文件改名 | 同时处理旧路径和新路径，更新两侧父目录；包含支持扩展名与非支持扩展名互改 |
| 目录新增、删除、改名 | 处理父目录和受影响子树缓存；清理旧路径下的索引、节点任务和摘要。删除后无法查询原类型时，结合已知路径缓存和事件类型判断 |
| 非支持类型文件变化 | 在进入刷新队列前忽略；目录事件不能被扩展名过滤误丢弃 |
| 点目录内部变化 | 按工作区根以下的相对路径段过滤；显式点目录根不误过滤；改名进入或离开隐藏范围时清理或补充对应可见节点 |
| 已展开且已加载目录变化 | 只重新枚举该父目录的一层，并更新差异，不遍历全部工作区 |
| 已加载但折叠目录变化 | 标记缓存失效，下一次展开再读；目录本身被删除时立即移除失效节点 |
| 未加载目录变化 | 不提前加载树节点；若路径索引已建立，更新或安排受影响子树的索引修复 |
| 监控缓冲区溢出或其他 Error | 标记缓存不可信，合并为一次恢复任务；重新校验已加载目录。仅在索引已建立或仍有请求时重建轻量路径索引，不读取全量摘要 |
| 根目录不可用 | 停止重复刷新，保留编辑内容并提示工作区不可用；提供重试，重新挂接监控后校验缓存 |

继续以现有 500ms 为事件合并起点，增加最长等待边界，避免持续写入导致刷新无限延后；每批相同父目录去重，刷新期间的新事件进入下一批。

初始化时先建立会话及监控，再读取目录快照；读取期间发生的事件保留并在快照后校验，避免初始化与监控接线之间漏掉变化。程序自己的保存、重命名和删除也经同一失效入口处理，合并重复通知。

### 4.5 取消与结果一致性

- 每次切换工作区递增工作区代次，取消并释放旧会话的任务、监控器、计时器和事件订阅。
- 每个目录的刷新携带修订号；结果提交前同时检查工作区代次、路径和修订号，拒收晚到的旧快照。
- 目录读取和监控刷新使用统一的目录任务协调，避免同一目录并发应用多个快照；不同目录只做受限并发。
- 路径索引扫描期间产生的变化先排队，扫描完成后应用；有缺失风险时重扫受影响子树，不能以旧扫描覆盖新变化。
- 枚举循环检查 CancellationToken。操作系统底层目录调用可能无法立即中断，因此仍必须以代次检查阻止过期结果提交。
- 路径归一化、工作区边界判断及大小写比较遵循平台语义；隐藏目录判断只检查根以下的路径段。
- 枚举及索引避免跟随符号链接或目录联接跳出工作区、形成循环；保持现有 MCP 路径授权校验。

### 4.6 当前文档通知与正文更新

**当前已集成的链路**：`StartCurrentFileWatcher` 为当前文件建立独立监控，事件经 500ms 防抖后调度至 UI 线程；`ReloadWatchedFileAsync` 调用 `DocumentService.ReloadAsync` 从本地磁盘读取候选版本，与上次保存正文比较后设置 `Protection.External`。`ShellWorkflowNotice` 通过属性通知显示外部变更提示；用户在 `CompareExternalAsync` 中选择“载入”后才替换共享正文，源码编辑器和阅读／预览随共享状态更新。这里重新读取的是本地文件，不涉及网络下载；仅刷新文件树或手动刷新预览不会重新载入磁盘正文。

当前实现在阅读和编辑状态下都先提示，不自动替换正文。本次继续采用这个默认行为，具体约定如下：

| 场景 | 通知及更新规则 |
| --- | --- |
| 非当前文档发生变化 | 更新相关目录、元数据、索引及摘要缓存；不读取该文档全文，不切换当前文档 |
| 当前文档正在阅读，或当前编辑内容已保存 | 重新读取磁盘候选，内容与保存基线不同时显示外部变更提示；用户选择载入后更新正文及可见阅读／预览内容，尽量保留阅读位置 |
| 当前文档存在未保存修改 | 显示外部变更提示，保留正在输入的内容、未保存标记和撤销历史；比较前提交编辑控件尚未同步的输入，再提供保留当前、另存副本、载入或取消的既有操作 |
| 用户选择载入 | 确认文档身份、候选版本和比较期间的编辑修订仍有效后，经统一内容通道更新正文和磁盘保存基线；载入是可撤销操作，不清空已有历史 |
| 用户选择取消、保留或另存副本 | 取消保留待处理提示；保留当前关闭本次提示但不写磁盘；另存副本不代表已载入外部版本，取消或失败时保留当前正文及提示 |
| 应用自身保存引发事件 | 读取结果与已成功保存的正文一致时，不重复提示外部冲突、不重载编辑器；事件仍参与目录和摘要失效；磁盘内容不同则不能按“自身保存”直接忽略 |
| 当前文件被外部删除、改名或暂时不可读 | 通知文件不可用并保留内存正文，允许另存、恢复原路径后的重试；外部改名不静默改写当前文档身份，也不自动打开其他文件；应用主动改名沿用既有工作流 |

工作区监控与当前文件监控可以同时报告同一变化，正文读取入口按当前文档合并处理。工作区路径过滤不应阻断当前文档的独立监控；即使该文档不在已展开目录中，也应收到通知。上述“一份工作区级监控器”不包含这一个独立当前文件监控器。

**本次需补齐的一致性保护**：

1. 不以修改时间必须严格增大作为内容变化的唯一门槛；收到相关事件后按修订核验候选，覆盖相同／回退时间戳和编辑器临时文件替换原文件的保存方式。比较仍按既有换行归一化语义，避免仅换行差异误报。
2. 正文读取使用文档打开代次、目标路径和读取修订号，完成后复核；同路径 A → B → A、连续外部写入或较旧任务晚完成时，不能提交旧候选。只切换文档而未切换工作区时也应生效。
3. 读取前后核对可用磁盘版本信息及期间事件修订；若读取期间发生新写入，继续安排最新核验，不能把读取完成时的最新修改时间直接当作旧正文快照的版本。临时锁定或替换窗口采用有限重试，失败保留提示与重试入口，不以空正文替代失败结果。

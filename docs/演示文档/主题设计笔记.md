# 为 Avalonia 文档工具建立一致的视觉规则

一个专业的桌面编辑器，需要统一的正文、菜单、图表和代码块。颜色、字体和密度应当是有含义的资源，而不是散在事件处理函数中的数字。

## 从语义资源开始

| 语义 | 用途 | 应检查的状态 |
| --- | --- | --- |
| 正文前景 | 普通文字与主要内容 | 明暗主题、选择、禁用 |
| 次要前景 | 提示、路径与辅助信息 | 对比度和长文本 |
| 表面与边界 | 面板、菜单、代码框 | 嵌套层次与圆角 |
| 强调色 | 选中项、焦点和主要操作 | 键盘焦点与作者颜色 |

## 用 AXAML 声明样式

```xml
<Style Selector="Button.document-action">
  <Setter Property="Height" Value="30" />
  <Setter Property="Padding" Value="8,3" />
  <Setter Property="CornerRadius" Value="4" />
  <Setter Property="Background" Value="{DynamicResource DocumentSurfaceBrush}" />
  <Setter Property="Foreground" Value="{DynamicResource DocumentForegroundBrush}" />
</Style>
```

这段样式需要宿主定义两个语义画刷。正文、偏好设置中的 MCP 示例、即时编辑中的代码与阅读代码块应复用通用控件，而不是分别拼出近似外观。

## 密度与可读性分别控制

文件数变多时，应允许用户调整文件列表字号。紧凑密度可以改变行距，不能让文字被固定高度裁断。工具菜单应完整展开；真正受窗口高度限制时才允许滚动。

## 交互状态必须一起设计

- 常态、悬停、按下、禁用和键盘焦点。
- 空选区、单块选择、跨段落选择和反向选择。
- 有作者颜色的文字与选择颜色的叠加。
- 打开、确认、取消、点击外部关闭和 Escape。

> 可读性比把所有元素都染成强调色更重要。

# 用 Markdown 写好一份 .NET 技术方案

一份好的方案既要让**代码正确**，也要让*读者容易理解*。本文以一个 Avalonia 桌面应用的文档编辑功能为例，展示从标题、列表到表格和行内样式的常用写法。

## 先写目标，再写实现

> 文档和代码一样，需要清晰的边界。
>
> > View 负责呈现，ViewModel 负责状态与命令，通用编辑能力由控件库提供。

先明确这次交付：支持本地 Markdown 文件，在源码、即时编辑和阅读之间切换；不把视图事件当作业务工作流的入口。

### 交付检查表

- [x] 把文档内容保存在独立模型中
- [x] 用命令连接工具条与编辑能力
- [ ] 在 win-x64 Native AOT 发布包中完成验收

### 推荐的实现顺序

1. 建立文档模型与服务接口。
2. 完成 ViewModel 的编辑、保存和撤销命令。
   - 同步操作保持简短。
   - 文件读写使用异步 API，并允许取消。
3. 用 AXAML 组合编辑器与工具条。
4. 验证错误提示、键盘操作和文档切换。

#### 命令的输入

输入是文档路径、原始 Markdown 和选区，不能把临时显示文本当作唯一数据来源。

##### 验证边界

选区以源码偏移保存；渲染时需要将其映射到可见文字，特别是包含 `<span>` 标记的段落。

###### 一条可以执行的验收标准

选择“目标文字”，设置颜色，撤销后原始 Markdown 完全恢复。

## 用表格比较视图

| 视图 | 使用场景 | 数据来源 | 验收重点 |
| :--- | :--- | :---: | ---: |
| 源码编辑 | 修改精确语法 | Markdown | 选区与撤销 |
| 即时编辑 | 一边写一边看 | 同一文档 | 混合字号与输入法 |
| 阅读 | 审阅与分享 | 同一文档 | 表格、图表和链接 |

表格中的竖线需要转义，例如 `A \| B`；示例 API 写成 `Task SaveAsync()`，避免把代码和正文混在一起。

## 一个可以复用的接口

```csharp
public interface IDocumentStore
{
    Task<string> ReadAsync(string path, CancellationToken cancellationToken);
    Task WriteAsync(string path, string markdown, CancellationToken cancellationToken);
}

public sealed class FileDocumentStore : IDocumentStore
{
    public Task<string> ReadAsync(string path, CancellationToken cancellationToken) =>
        File.ReadAllTextAsync(path, cancellationToken);

    public Task WriteAsync(string path, string markdown, CancellationToken cancellationToken) =>
        File.WriteAllTextAsync(path, markdown, cancellationToken);
}
```

接口让 ViewModel 可以使用测试替身；文件 IO 留在服务里，视图只绑定状态和命令。

## 混合字号与颜色

同一行的<span style="font-size:48px">大字</span>和普通文字应共享自然基线，<span style="font-size:12px">小号说明</span>也应完整显示。点击这一段、拖选不同范围，再使用 Shift + 方向键扩展选区，检查行盒是否跳动。

<span style="color:#C92A2A">红色警示文字</span>、<span style="background-color:#FFF3BF">浅黄背景</span>与<span style="color:#30953B;background-color:#ECF7EC">绿底深绿文字</span>都应在选择后仍然清楚，取消选择后恢复原样。颜色面板修改的是草稿，点击“应用”才写入文档。

转义的语法如 \*普通星号\* 不应该变成强调；`<T>`、`&` 与 `` `反引号` `` 应忠实显示。😊 中文、英文、数字 123 与 emoji 都需要参与选择测试。

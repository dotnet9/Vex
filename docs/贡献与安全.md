# 贡献与安全

## 维护方式

先阅读 [仓库导读](概要设计.md) 和 [开发与验证](development/开发与验证.md)，沿用模块、MVVM、消息及资源边界。常见问题应修在所属服务或共享库中，避免在界面层重复保存、渲染和权限逻辑。

对照原型时，说明具体场景、窗口尺寸、语言与明暗模式；修改配色和排版时复用语义资源 Key。功能实现和设计目标分别记录，不以截图相似替代交互与文件安全验收。

提交说明要清楚表达问题、改动和验证。构建输出、临时 NuGet 源、个人文档、Token、私钥和本机配置不进入版本库。提交、推送和发布按维护任务的明确授权执行。

## 数据与协议边界

文件、附件、远程图片、链接和 Markdown 内容可能不可信。删除、关闭未保存内容、覆盖、导出和打开外部资源要遵守各自确认与错误处理规则。不得为了测试覆盖真实笔记或改变用户默认程序。

MCP 默认关闭，默认监听本机回环地址，使用 Bearer Token 和路径范围约束；修改与保存等动作通常需确认。当前配置含 Token 字段，备份与客户端配置也可能含令牌，应当视为敏感信息。它不隔离同一系统账户下的恶意程序，详见 [MCP 说明](MCP功能实现方案.md)。

## 报告问题

普通缺陷可在 [Issues](https://github.com/dotnet9/Vex/issues) 提供版本、系统、最小复现、预期与实际结果，以及脱敏截图或日志。

可利用漏洞、私钥和令牌不要公开提交。优先使用 [GitHub Security](https://github.com/dotnet9/Vex/security) 的私密报告入口；若未启用，通过 [项目首页](../README.md) 中的维护者公开联系方式请求私下报告渠道。签名材料只保存在本机或受控 CI 配置中，泄露后需撤销或轮换。

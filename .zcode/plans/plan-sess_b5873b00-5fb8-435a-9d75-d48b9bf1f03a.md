# 即时编辑路线一：muya 模型架构对齐

## Context

上一轮分析已定性：MarkdownLiveEditorView 的「每块双态呈现 + 失焦即退出提交 + 拆块整表重建」架构是光标/回车/空白点击反复出问题的根因。用户拍板路线一——按 muya 模型重构为块树+就地编辑。

现状关键事实（三路调查结论）：
- **Core 已就位但被架空**：`src/Markdown.Core/MarkdownBlockEditorCore.cs`（Enter/Backspace/MergeForward 纯逻辑，`BlockEditResult(Changed,FocusIndex,Caret)` 契约）+ 15 个 muya 矩阵翻译单测全绿；但视图侧 `SplitBlock`/`MergeBlock`（MarkdownLiveEditorView.cs:863-902/841-861）是其**逐行内联复制品**，Core 在 UI 中零调用（仅 EnsureFirstBlock 被用）。
- **整表重建是常态**：拆块/合并/缩进/标题转换/插块全部走 `RebuildBlocks()`（620-652，ClearItems 全量重建）；`WindowedStackPanel` 其实有完整增量 API（`InsertItem/InsertItemBefore/RemoveAt`）。
- **编辑成本高**：每键击 `UpdateRichText()` 重渲染渲染态（Viewer 路径=重解析整块）+ 宿主全文序列化。
- **焦点链脆弱**：BeginEdit/CommitAndRender 换层 + LostFocus→CommitIfFocusLeft + RevealBlock 4 轮布局补偿。
- muya 参考源：`E:\github\temp_files\marktext\packages\muya`（@muyajs/core MIT），键盘矩阵基类 `src\block\base\content.ts`（enterHandler/backspaceHandler/tabHandler/deleteHandler/arrowHandler，子类覆写），有大量 enter 行为 spec 可翻译。
- InlinePresenter 链接仅样式不可点击、不支持内联图片/数学 → **用户已拍板：扩展 InlinePresenter 支持内联图/数学，全段落单表面；链接 Ctrl+Click 打开、单击落光标**。

## 目标架构

1. **文本块单表面**：Paragraph/Heading/ListItem/Quote 全部常驻 `TextBox+MarkdownInlinePresenter`（源码即显示、语法标记隐藏、富文本样式）——点击=原生焦点落光标（块内不再走 tunnel/FindNearestBlockIndex），失焦不退出不提交（模型实时同步）；内联图片/数学以嵌入对象绘制（源码 span 隐藏，caret 进入显源码，muya 同款）。
2. **结构操作收回 Core**：Enter/Backspace/MergeForward/Convert/Indent/Outdent/续引用全部 Core API+单测，删视图复制品。
3. **增量结构更新**：拆块=InsertItem、合并=RemoveAt+前块续接、转换=单块刷新、插块=AddItem；Quote 分组仅在触碰边界时局部重建；RebuildBlocks 只留给 SetText/主题变化。
4. **复杂块保留 overlay**：代码（透出高亮）/mermaid（源码+图）/表格（单元格）/frontmatter/HTML 块维持现三模式，但焦点进入模型统一。
5. **链接 Ctrl+Click 打开**（复用 Viewer 链接打开通道），单击落光标。
6. **Enter 矩阵补齐 muya 缺口**（列表 Tab/Shift+Tab 缩进降级、quote「>」续引、跨块选区删除）+ 单测翻译扩展。

## 契约冻结（重构不破坏）

`SetText` 静默无事件 / `Text` 全文序列化 / `Selection` 源码偏移映射 / `MarkdownChanged`+`SelectionChanged` 触发时机（每键击，SetText 抑制）/ Attach-Detach 单实例 / 应用级 Ctrl+Z 走 Shell 历史+SetText 回灌（窗口 Tunnel 优先）/ `EditorActionKind` 全部落点 / 视觉树类名契约（MdParagraph、MdTaskMarkerBox、MdTable*、MdQuote、MdEditorScroll、块内 TextBox、`MarkdownBlockView` 类型名、TextPresenter 层级供 CenterCaret）/ 属性面（DocumentPadding、CaptureState、NavigateToSourceLine(line,beginEdit)、ApplySpanStyle 等全保留）。

## 分阶段实施（每阶段 harness 全绿后提交，提交前请示）

### 阶段 0（约半天）：过渡笔入库 + Core 收编
- 提交当前工作区遗留（路线二补丁：透明背景/FocusLastParagraph/Tunnel + Logging 埋点 + Logging 包引用）为独立过渡笔。
- `SplitBlock`/`MergeBlock` 改调 `Core.Enter/Backspace/MergeForward`，删内联复制品；Core 增 `ConvertBlock`（标题/列表/引用转换）、`Indent/Outdent`（列表缩进降级）API + 翻译测试。
- 验证：`fix-regression`、`instant-menu`、`elements` 全绿。

### 阶段 1（约 1 天）：增量结构更新，消灭整表重建
- 拆/合/转换/插块改走 WindowedStackPanel 增量 API；Quote 分组逻辑提取成函数，仅边界触碰时局部重建受影响组。
- `RebuildBlocks` 只剩 SetText/外观属性两条路径；`RevealBlock`/`FocusBlock` 适配增量插入的焦点保持。
- 验证：+`round-trip`、`case-sensitive path`、`selection-style`。

### 阶段 2（约 1.5-2 天）：文本块单表面（纯文本场景收官）
- MarkdownBlockView：无内联图/数学的文本块常驻编辑器——删 BeginEdit/CommitAndRender 换层与 LostFocus 提交（`BeginEdit` 退化为 focus+caret 兼容 API）；去掉每键击 `UpdateRichText` 重渲染（InlinePresenter 即显示层）。
- 块内 PointerPressed 不再 tunnel 拦截（原生 TextBox hit test 落光标）；空白点击 tunnel→FocusLastParagraph 保留。
- Ctrl+Click 开链接：InlinePresenter hit test 取 LinkUrl run → 复用 Viewer 打开通道。
- **新增 headless 真实输入探针**（HeadlessWindowExtensions.MouseDown 真实 hit test，替代 RaiseEvent 直发）钉住「点击文字任意位置光标就位」「失焦不丢内容不换层」。
- 验证：+`editing-tools`、`blog-frontmatter`、真实输入探针。

### 阶段 3（约 1-2 天）：InlinePresenter 扩内联图/数学，全段落单表面
- **先半天 spike**：Avalonia TextFormatter 自定义 DrawableTextRun/EmbeddedObjectRun 可行性验证（`MarkdownInlinePresenter.CreateTextLayout` 返回含图片/数学绘制的自定义 TextLine）；失败回退=该类段落暂保留 Viewer 双态并在交付说明标注。
- 图片 run：按 ImageBasePath 解析位图、行高缩放绘制、按需缓存；行内数学 run：CSharpMath 渲染（Sylinko.CSharpMath.Avalonia 已在包基线）。源码 span 隐藏，caret 进入该 span 显源码编辑。
- `MarkdownTextRunParser` 增 Image/Math run 标记；段落 `useViewer` 分支删除，Viewer 仅剩代码高亮透底/mermaid/表格/frontmatter。
- 验证：图片/数学段落 round-trip 往返、编辑回归全绿。

### 阶段 4（约 1 天）：矩阵补齐 + 清理
- muya 缺口：列表 Tab/Shift+Tab 缩进与降级（键盘直达）、quote「>」续引、跨块选区 Backspace/Delete 删除、空列表项 Enter 降级核对。
- 翻译 muya `enterHandler/backspaceHandler` spec 到 Core 测试（15 测→约 30 测）。
- 清理 RebuildPreservingEdit 死分支；评估撤销粒度（保持接口，仅内部优化）。
- 验证：harness 即时编辑相关全模式 sweep + 全新 AOT 冒烟 + 真机手测（点击任意位置光标、连敲回车、列表缩进、引用续行、内联图/数学段落编辑、Ctrl+Click）。

## 风险与预案

- TextFormatter 嵌入对象是唯一技术不确定点 → 阶段 3 先 spike 后动工，有回退路径。
- 探针 RaiseEvent 失真点（fix-regression 的 KeyDown 直发等）→ 新增真实输入探针双保险，旧探针以「存活优先」原则最小适配。
- 每阶段独立可交付：任一阶段后停下，产品都处于全绿可用状态。

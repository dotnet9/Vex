# Vex 原型设计准则

本文件是 `design/` 后续调整的共同依据。适用于产品范围、界面、交互、配色、正文排版与原型验收。修改原型时先遵守本文件；新的产品决策经确认后同步更新本文件与对应验收入口，避免文档和页面各说各话。

## 1. 产品定位与范围

- Vex 是以文章为中心的桌面 Markdown 工作区，核心路径是“打开 → 写作 → 整理章节 → 保存 → 导出”。工具为内容服务。
- 支持 Windows、Linux、macOS；对应安装流程为 EXE、DEB、DMG。窗口缩窄继续使用桌面交互。
- 保留既有菜单、八种布局、文件导航、大纲、章节详情、导图、偏好与新手引导。常用动作直接可达，低频动作进入菜单或辅助面板。
- 以当前原型作为功能与视觉基线，渐进修改。原型效果通过评审后，再安排应用实现；原型通过不代表原生应用已经实现或验收。
- 当前保留 16 套界面配色与 27 套正文排版。减少选择负担通过推荐和用途说明实现，不删除已有方案。

## 2. 视觉层级与空间

- 第一层是文章内容；第二层是当前文档、视图、保存；第三层是导航、状态与辅助说明。
- 顶部中央统一切换布局。编辑工具靠近编辑内容，排版入口靠近阅读区域，大纲、文章信息与章节详情共用右侧辅助面板。
- 常规间距使用 4 / 8 / 12 / 16 / 24 / 32px；组件圆角以 4 / 6 / 8px 为主，窗口和主要浮层可用 10px。阴影用于悬浮层级，不给每块内容加阴影。
- 工具栏、状态栏和需要阅读的辅助文字使用 12–14px；正文默认 16–18px 起。宋体、等宽等差异由内容用途决定。紧凑选项优先收紧行距与间距，正文不小于 16px。
- 正文行高通常为 1.8–2.0，紧凑约 1.65；阅读区域限制行宽，源码、宽表格和图表保留所需空间。
- 标题栏外观、语言与窗口按钮的垂直中心一致。跨平台保留各自窗口按钮习惯。
- 软件窗口外的舞台固定为 `#EAECEA`。明暗、配色只改变软件内部；Portal 菜单也属于软件内部。Logo 保留品牌墨青 `#24766B`。

## 3. 配色资源与语义 Key

所有方案使用相同的语义 Key，风格差异体现在值。禁止用一枚高饱和颜色同时担当小字、装饰、按钮底色和按钮前景。新增方案应同时提供浅色与深色值，不从浅色机械反相。

| 资源 Key | 用途与约束 |
| --- | --- |
| `--bg` / `--paper` / `--panel` | 工作区、文章纸面、辅助表面，以色温与明度建立层次 |
| `--fg` / `--muted` | 正文与辅助文字，均须在实际承载表面可读 |
| `--accent` | 链接、小字强调、选中内容的文字；按文字对比度校正 |
| `--accent-decoration` | 配色原始特征色，用于非信息性装饰和色点 |
| `--accent-soft` / `--hover` / `--pressed` | 选中浅底、悬停底、按下底；前景仍须可读 |
| `--primary` / `--on-primary` | 实底主按钮及其专用前景，独立配对 |
| `--primary-hover` / `--primary-pressed` | 主按钮悬停与按下，保持与前景的对比度 |
| `--on-accent` | 旧组件以 `--accent` 作底时的前景，不能代替 `--on-primary` |
| `--border` / `--control-border` | 轻分隔线 / 识别控件所必需的边界，二者强度不同 |
| `--focus-ring` | 键盘焦点，必须可见且不依赖悬停 |
| `--fg-disabled` | 禁用文字，配合禁用语义、虚线边界等状态，不叠加多层透明度 |
| `--status-error` / `--status-error-bg` | 错误文字及背景，配合具体原因与可执行动作 |
| `--status-success` / `--status-warning` | 成功与提醒，含文字说明，不能只用红绿点表达 |

方案辨识度来自整体色温、饱和度和表面关系：石墨保持中性，海蓝沉稳，晴蓝明快，沙金温暖；陶朱与赤陶、墨青与水青等相近色系也要有可见差异。保留品牌默认，不把每个方案都改成同一套颜色。

共享适配入口是 [`assets/design-system.js`](assets/design-system.js)，控件状态在 [`assets/design-system.css`](assets/design-system.css)。`desktop-resources.js` 保留来源资源快照；原型适配与对比度校正集中在共享层。现有 Key 不随展示名变化，不同样式不得共用同一个 Key。

## 4. 对比度与状态

- 普通文字的实际前景/背景对比度至少 4.5:1；大字至少 3:1。本轮正文标题也按 4.5:1 验证，给多配色组合留出余量。
- 识别控件所必需的边界、焦点和状态标识至少 3:1；装饰分隔线不按控件边界处理。
- 检查实际合成后的背景，包括浅底标题、引用、选中和悬停。只比较色板原值不算验收。
- 每类交互控件定义默认、hover、pressed、selected、focus、disabled 状态；输入还要定义 readonly、error。按下态应与悬停有差异，焦点不能被阴影或裁切遮住。
- 当前配色、排版和语言用勾选、文字或语义状态表达；不能只换颜色。错误应显示动作名称、内容是否保留与重试入口。
- 主按钮使用专用底色和前景；危险动作明确命名，例如“从工作区移除”“不保存并退出”，说明实际影响。禁止用含糊的“确定”掩盖数据后果。

## 5. 选择面板与菜单

- 配色默认推荐 5 套，排版默认推荐 6 套；“全部 16 套 / 全部 27 套”一键可达。当前方案即使不在推荐里，也要可见。
- 每套方案包含简短中文用途；名称帮助辨认，用途帮助决定。
- 正文排版卡片必须直接展示各自的标题、正文、引用效果，使用真实字号。不能通过先选中、再到另一块区域看结果的方式比较。
- 方向键、Home、End 只移动卡片焦点，Enter / Space 或点击才应用。选择排版后保留弹层，便于继续比较。
- 排版弹层固定头部、筛选和紧凑开关，卡片区独立竖向滚动；不压缩卡片固有高度，不让预览溢出卡片。小窗口减少列数。
- 标题栏的文件、编辑等一级菜单、所有级联、外观和语言面板统一为 `--title-menu-width: 248px`，以文件菜单为基准。正文排版和工作区布局是内容面板，不套用此宽度。
- 长菜单先使用紧凑间距，仍超过窗口时在面板内部滚动；级联靠近边界时翻转、限位。键盘到达末项时必须滚动到可见位置。
- Escape 关闭当前浮层并返回触发位置；点击外部可关闭非模态浮层。模态对话框包含焦点约束，取消回原文档与阅读位置。

## 6. 写作状态与数据保护

- 文档内容保持单一来源。切换明暗、配色、正文排版或布局，不得改写 Markdown、清空历史或无故重置选区与文章位置。
- 章节改名、正文修改、移动、升降级与删除可撤销，导图、大纲与正文一致。
- 保存失败时正文、未保存状态和撤销历史保持；错误持续可见，直到重试成功或用户明确处理。继续编辑不能悄悄清掉失败标识。
- 导出失败提供独立重试，保留正文与排版；导出 HTML 成功不代表 Markdown 已保存。
- 外部变更先提示、比较，再由用户选择保留当前、下载当前副本或载入外部版本；取消保持当前位置。载入外部版本可撤销。
- 恢复草稿先展示来源和内容，再恢复为独立文档；不覆盖正在写的文章。恢复不等于已保存，仍显示未保存状态。不可读草稿保留原始数据。
- 菜单退出与标题栏关闭共用未保存保护。保存或保留草稿失败时窗口保持打开；取消继续编辑。
- 原型通过浏览器下载 Markdown / HTML 副本，不能宣称已经写回来源文件或完成下载。显示“下载已发起”，由用户在浏览器确认；安装、系统授权、PDF 等演示也要如实标明。
- 外部版本场景是内存演练，不代表浏览器已实现真实磁盘监听或自动合并。应用实现需单独验证读写、冲突、输入法和系统行为。

## 7. Markdown、表格与图表

- 表格采用内容自适应列宽，短列不无故留白；宽表格在自身容器内横向滚动，不撑宽整篇文章。
- 公式、代码字体和图表使用原型内本地资源，离线评审可用。图表模板以 `mermaid-catalog.js` 清单为准，目前 22 类。
- 图表优先保证标题、轴、节点标签清晰。宽甘特图、C4、XY 等保留可读尺寸并局部滚动，不为塞入窗口把整图缩到字不可读。
- 导图以章节标题和正文摘要为主，“文档”“H2”等提示与标题同行、减弱，不独占突出一行。
- 排版预览、实际文章、HTML 导出与复制文章共用规则。导出为独立浅色纸面，脱离软件主题仍须可读。

## 8. 验收门槛

每次涉及行为的调整，先检查受影响的真实任务，再回归相关基线。不为无关小改动重复运行全部矩阵。

| 范围 | 必查内容 |
| --- | --- |
| 配色与排版 | 16 × 2 × 27 组合；正文、各级标题、链接、引用；主按钮三态；必要边界与焦点 |
| 选择体验 | 推荐/全部、当前标记、27 张独立预览、键盘浏览不误应用、紧凑布局 |
| 尺寸与平台 | 800×480、1024×768、1440×1000；三平台标题栏、菜单等宽、长菜单末项可达 |
| 内容不丢 | 主题/排版/布局切换后的正文、选区、历史和位置；章节修改后撤销 |
| 真实任务 | 打开实际 Markdown → 编辑 → 整理章节 → 保存副本 → 导出 HTML，检查文件内容 |
| 异常分支 | 保存失败重试、导出失败重试、外部变更比较/取消/载入/撤销、草稿恢复、未保存关闭取消 |
| 阅读细节 | 自适应表格、甘特/C4/XY 标签、导图弱提示、中英文长名称与四种界面语言 |
| 离线与静态 | 本地资源齐全、无脚本报错、无丢失资源、文档链接可达、改动无空白错误 |

常用入口：[`Usability-Review.html`](Usability-Review.html)、[`Appearance.html`](Appearance.html)、[`Vex.html`](Vex.html)。异常演练参数为 `scenario=save-error|export-error|external-change|draft`，配合 `preview=1` 使用隔离偏好。

验证命令：

```powershell
node design/scripts/verify.cjs
# 浏览器检查需要环境中可用的 Playwright 和 Edge，以及本地预览服务。
$env:VEX_BROWSER_CHANNEL = 'msedge'
node design/scripts/browser-design-principles.cjs
node design/scripts/browser-workspace-chrome.cjs
node design/scripts/browser-resource-review.cjs
git diff --check
```

浏览器检查报告与截图输出到仓库忽略的 `artifacts/prototype-*`。用户验收前保持工作区改动，不暂存、不提交。

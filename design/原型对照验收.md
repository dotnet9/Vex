# 原型与实现对照验收

本轮以 `design/index.html` 为交互和布局基准，使用同一 Markdown、Aurora 配色、相同窗口尺寸分别截取浏览器原型和真实 Avalonia 主窗口。检查覆盖 1280 × 820、980 × 640、浅色/深色、即时编辑/源码对照/阅读/导图，并单独检查排版卡片、摘要设置和节点全文面板。

## 本轮修正的实际问题

- 源码和阅读视图绑定到了各自的 ViewModel，导致工作台显隐条件失效；现已明确绑定 Shell 的工作台状态。
- 打开文档时不再自动进入首个标题的编辑态，避免出现重复标题。
- 在阅读视图统计查找命中数时，保留当前视图；需要定位具体命中时才进入源码。
- 排版变化保留即时编辑活动块和选区；隐藏的即时编辑器不再随每次源码输入重建。
- 导图颜色使用宿主动态资源，修正明暗切换后残留旧主题色的问题。
- 原来的打字机设置未控制滚动，已实现源码和即时编辑的实际居中行为。
- 即时编辑原来只处理配对退格，未处理成对字符输入；现已补齐插入、选区包裹、跳过已有右半边，并保留普通 Unicode 文本输入。
- 引导的聚光范围改为实际段落和根节点位置；关闭动画后也会刷新；长语言文案可换行并在窄窗内滚动。
- 引导重开时清理旧动画与聚光状态；开启过动画后再关闭动画，重新打开也会立即跟随当前偏好。

## 保留的产品差异和验收边界

- 真实侧栏显示工作区目录、文件夹层级、排序和修改时间，顶部路径来自实际文档；原型使用固定样例。截图不会伪造文件系统状态。
- 代码和表格可以分别控制显示，比原型合并的开关更细。
- 产品使用 Markdown AST 统计；原型简易统计的数字不作为正确性标准。
- 原生窗口装饰、字体栅格化和浏览器存在平台差异，未声称逐像素一致。
- 验证使用无界面的 Chromium 和 Avalonia.Headless，可在锁屏时继续。NativeAOT 另用真实发布 EXE 做启动存活检查。中文输入法预编辑、多显示器 DPI、实体鼠标和系统文件选择器仍需解锁后人工体验。
- AOT 日志保留了第三方库裁剪/分析警告，以及旧 Prism `DialogWindow` 模板的反射绑定诊断。当前应用浮层使用 Ursa，相关流程已在真实主窗口的无界面回归中覆盖；原生 EXE 启动检查不能替代全部功能的原生键鼠验收。
- 共享导图当前构造所有可见节点，极大导图全部展开的内存与交互上限仍需专项性能优化。

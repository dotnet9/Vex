Git 状态标识 · 前导状态槽（VS 经典语言）

标识与文件图标分开：每行在图标前有一个独立的状态槽——受管未变化挂灰锁，变更按对应字形呈现，不在 git 管控内则状态槽为空。图标字形（octicon 逐字）与 Git 面板语言沿用上一版，本版只改树内呈现语义与位置。

01前导状态槽语义（VS 经典口径）

状态前导字形颜色octicon 来源适用面
受管 · 未变化 lock 灰 · VexMutedBrush 口径 lock-16（逐字） 文件树（文件行）
修改 / 重命名 check 红（VS 经典红勾） check-16（逐字） 文件树（文件夹聚合同色）
新增（已入 git 管控，暂存待提交） plus 绿 plus-16（逐字） 文件树（文件夹聚合同色）
未跟踪（不在 git 管控内） （空槽） — — 无前导字形
冲突 / 删除 / 冲突已解 alert / removed / check 橙 / 红 / 绿 alert-16 / diff-removed-16 / check-16（逐字） 仅 Git 面板
三条铁律：① 受管的文件一定有前导字形——干净挂灰锁，有变更挂对应字形； ② 未跟踪 = 不受管控 = 状态槽为空（连锁都不挂，与 VS 截图口径一致）； ③ 文件夹不是 git 实体——只聚合并展示变更字形（勾/加号），干净文件夹不挂锁。 重命名在树内走红勾（VS 经典把重命名按变更呈现）；蓝箭头 diff-renamed 保留在 Git 面板。

02.5三条铁律（用户口径逐条落位）

默认是锁
受 git 管控且无变化的文件：前导槽挂灰锁——一眼分辨"这棵树在 git 里"。锁只在文件行出现，文件夹不挂锁（夹不是 git 实体）。
已变化用对应图标
修改/重命名=红勾，新增（已入管控）=绿加号，冲突=橙警（面板）。文件夹聚合后代最强变更字形，干净文件夹无字形。
未管控就空白
未跟踪文件不在 git 管控内：状态槽为空，什么都不放——和 VS 截图口径一致，"有没有字形"本身就是"在不在管控里"的信号。
